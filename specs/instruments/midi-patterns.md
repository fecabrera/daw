# MIDI patterns and oscillators

Implementation requirements and design records. For user instructions, see the [user guide](../../docs/views/editor.md).

The first implementation adds MIDI tracks, immutable pattern sources, a basic piano roll in Editor, and a layered instrument in Units. Audio tracks retain their existing source behavior. Beat tracks, effect chains, and instrument graph editing remain pending.

## Controls

1. In Timeline or Editor, choose Track > Add MIDI track. Both views support MIDI track/pattern creation, MIDI paste, and track duplication through the same guarded actions.
2. Double-click empty space on a MIDI lane in Timeline or the Editor track strip to create a one-beat pattern at the snapped position. Creation selects the clip and stays in the current view. Shift bypasses snapping. Existing saved pattern lengths remain unchanged.
3. Double-click a MIDI clip or choose Edit clip from its context menu to open its pattern. Editor shows the selected track: a clip strip below the ruler and all its MIDI patterns in one piano roll. Each pattern has a visible border, including contiguous patterns. Select a clip in the strip or edit its notes to make it primary without moving the viewport. Use the track-header dropdown in the full-height left panel to switch the editor to another track. It selects that track’s earliest clip, or shows its empty editor when it has no clips. With no track, Editor prompts for a selection; audio clips show that their editor is pending.
4. Click and drag empty piano-roll space to select all notes that intersect the selection box. Selection can span patterns and gaps on the selected track. Shift-click toggles a note without clearing other selected notes, including notes in other patterns. Shift-drag in empty space toggles the notes inside the box against the selection at the initial press; notes outside it retain their selection. Repeated occurrences of one source note toggle once per clip. The box captures its Shift state at the initial press. A Shift-click on empty space keeps the selection; a plain empty-space click clears it. Hold Command on macOS or Ctrl on Windows/Linux while clicking empty space to add a grid-sized note, or while dragging to draw from the start point to the end point. The modifier at the initial press selects the gesture mode; changing it during the drag does not switch modes. The starting row fixes its pitch. Drawing backwards uses the ordered time range. Preview the new note and same-pitch neighbor trims, splits, and removals; commit them together on release. Different pitches retain their notes and can sound together. Drag a note body to change its start and pitch. If the note is selected, move the whole selected group with one time and pitch displacement, including notes in different patterns. Hold Option on macOS or Ctrl on Windows/Linux during the move to duplicate those notes. Copies have new IDs and retain note duration and velocity; originals stay intact. The copy modifier can change during a move, and its state at release decides whether to move or copy. Select the moved notes or copies after release. Clamp the group together at source bounds and the MIDI pitch range to retain its spacing, allowing one-tick rounding between differently stretched patterns. Shift bypasses time snapping. A drag with no effective displacement creates no copies and does not mark a change. Drag either edge of a selected note to resize the whole selected group by one shared project-time change, keeping each note’s opposite edge fixed. Clamp the group when any note reaches a pattern boundary or its one-tick minimum length. Differently stretched patterns round the change to source ticks. Dragging an unselected note edge resizes only that note. Holding the copy modifier on an edge still resizes without duplication. Notes preview until release; changes across patterns commit in one batch. Escape or focus loss cancels a drag and restores the previous note selection. Double-click without Shift or secondary-click deletes a note. Repeated Shift-clicks toggle selection without deleting notes. Delete/Backspace removes all selected notes in one transaction; the pattern context menu’s Delete note removes its selected note. These keys do not delete the containing clip in Editor.
5. Subdivisions and snapping use the shared Timeline grid in project time. Pattern edges, note drawing, note moves, and note resizes snap to absolute ruler positions within six logical points, with bars before beats before visible subdivisions. Positions outside that radius remain free. Clamp at source/project bounds before snapping. Shift bypasses snapping for each gesture and can change while dragging. Convert the shared result to source ticks for trimmed, repeated, and stretched patterns. Note gestures retain source limits and one-tick minimums; body-edge clip expansion pads the source instead of stopping at its old length. A click-created note lasts one visible project subdivision, converted to source ticks. Notes clamp to the pattern and MIDI pitch range. Velocity is 1–127, with a default of 100. Select a note and secondary-click the pattern header to adjust velocity or use Delete note; these controls do not add a permanent row above the piano roll. Editor uses the same project ruler, playhead, loop selection, snapping, and toolbar zoom control as Timeline. Its horizontal zoom and scroll stay independent; the zoom control has the same design and position in the playback toolbar. The ruler, track strip, pattern borders, notes, and playhead share project time and the same horizontal transform. Display trimmed ranges, stretch timing, and visible repetitions at their arrangement positions; editing a repetition updates that clip’s source. Piano keys stay pinned while notes scroll. Below half a pixel per repetition, show pitch coverage; zoom in to edit individual notes at that density. Empty gaps do not create patterns. Seeking and left-edge expansion clamp at project zero.
6. Drag either edge below a pattern’s header in Timeline or the Editor track strip to resize its source and visible clip range. Expansion pads the source without using its current length as a limit. The right edge changes its end. Snap the edge’s project position, rather than rounding the drag distance; off-grid patterns can reach the ruler grid. The left edge moves the clip start, crops or pads the source, and adjusts note ticks so retained notes keep their project timing within sample-frame rounding. Extending left adds space before existing notes. Left resizing keeps the clip end fixed within tick/source/stretch frame rounding. Remove notes wholly outside the new bounds and shorten crossing notes. Preview until release; Escape or focus loss cancels. The minimum source length is one tick. Shift bypasses snapping.

### Envelope components

Envelope is a generic note-driven modulation source. Each layer can hold multiple independent instances, displayed as Envelope 1, Envelope 2, and so on. Each instance retains its stable ID, ADSR, presence, power, and collapse state. Per note creates independent ADSR state for each note. Retrigger uses one shared envelope that restarts on every note-on. Legato restarts only for the first held note. Shared modes release after the last held note ends.

Amplitude is a separate optional audio stage per layer with a level control (silence through +12 dB, default 0 dB). Its Level strip uses the shared 90-point strip width, including 10-point padding on each side, in both regular and compact layouts. Opening modulation keeps that width. Its modulation controls and Auto-filter's controls share Source, Parameter, Amount, Power/Mod N footer strips and an oscillator-style Plus strip. Closed Source and Parameter selectors use the standard 11-point unit text in these units. Envelope places its Timing knob and compact Mode dropdown in the first body column. A 10-point icon-free header dot toggles modulation strips on the right while keeping regular controls visible. It shares the unit enable control's painting and 22-point click target, with the theme's secondary color instead of the enable accent. Filled means expanded; hollow means collapsed. Hover/focus shows a circular halo. The receiving unit saves `modulation_open` in the project; toggling marks the project modified through the normal instrument/effect edit. Missing fields default closed. Header controls do not start collapse or reorder gestures. Each connection has its own stable ID and can be removed from its strip's context menu. New connections start with no source, amount zero, and power on. New Envelope instances are unconnected. Removed instances retain their ID/settings; re-addition restores the first removed instance before appending another. Installed Amplitude is a clean no-op when added again.

Assigned parameters show a small status dot beside their base-value readout, using the modulation toggle's secondary theme color. Filled means at least one enabled, nonzero connection has an enabled, available source and an enabled destination, or a nonzero internal LFO is active. Hollow means connections exist but none are active. Hover the dot or knob to list sources, signed amounts, inactive reasons, possible range, and current processed values. Click the dot to open that unit's saved modulation controls; this does not change the base value or start a knob/unit drag.

A thin outer arc shows the possible held-note modulation range. Combine connections to the same source before calculating bounds so opposite amounts cancel. Clamp the arc and live markers to the existing knob scale; hover still reports processed values outside that scale. Keep the original pointer, accent arc, and readout at the base value. Separate moving dots show processed values from callback block snapshots, including smoothing and DSP bounds. They appear during playback; the UI does not run another envelope or simulate phase. Auto-filter Frequency includes its internal bipolar LFO and shows both stereo channels. Amplitude shows the highest active voice gain before velocity, layer gain, and voice summing; it includes the note gate and bypass crossfade. Static Amplitude ranges describe held notes, while live values also follow note attack/release. Telemetry handles are prepared and retired outside the callback; callback publication uses preallocated storage and atomic writes without allocation or locks.

Sources are identified by layer/unit IDs, not list positions. A single source can feed several parameters without advancing more than once per sample. Amplitude accepts per-note or shared envelopes and shared LFOs in its instrument. Auto-filter and Drive accept only shared sources from their own MIDI track; audio tracks and Master have no instrument source. Connected track-effect sources cannot switch to Per note until disconnected. Per-note-to-shared aggregation, cross-track control, oscillator modulation, audio sidechains, and arbitrary graph routing are not implemented.

Amplitude combines per-note contributions relative to the 5 ms note gate, so full depth reproduces the original amplitude ADSR and zero depth retains the gate. Shared contributions scale that result; the final held notes retain the shared release without reviving earlier ended notes. Amplitude power bypasses its level/modulation to the note gate. Envelope/route enable and parameter changes fade over 5 ms. Off envelopes continue advancing. Auto-filter sums offsets for frequency (±6 octaves), resonance (±10 Q), output level (±24 dB), and Dry/Wet (±1), then applies parameter bounds. Its internal LFO remains independent; external offsets use 1 ms smoothing. Drive also exposes Volume (±24 dB), Gain/Tone/Color strength (±1), and Color frequency (±3 octaves), using the same source routing, smoothing, saved visibility, and indicators; see [Drive modulation](../effects/drive.md#envelope-modulation). Modulation Amount is signed and resets to zero.

Instrument version 3 stores envelope and LFO instance lists and Amplitude settings/connections. Missing LFO lists default empty. Version 1/2 amplitude envelopes migrate into a generic Envelope plus Amplitude with an explicit full-depth per-note connection, preserving ADSR, power/collapse settings, and sound. Previously unconnected filter envelopes become additional generic Envelope instances without connections. Auto-filter and Drive retain their version-1 settings with optional modulation lists; missing lists default empty. Validate IDs, settings, target parameters, finite bounded amounts, source scope, and note-mode compatibility atomically. Removed sources remain valid references but contribute no modulation. Compatible edits and additions retain source/voice state using prepared storage; note-mode/topology changes reconstruct state through the existing renderer transition.

### Split at the playhead

`Project::split_clips` divides every requested clip that strictly contains the playhead frame and returns the new clip IDs. Clips that do not contain the frame stay unchanged. The original clip keeps its ID and ends at the playhead. The new clip starts there. The edit is one transaction: a missing clip or an invalid pattern leaves the project unchanged.

Audio uses `Edit::Split`. It keeps the source recording, name, and color. A loop keeps its source offset and shifts its phase by the left length. A clip without a loop moves the right piece’s source offset forward by that length. Stretch stays on both pieces.

MIDI notes follow `MidiNoteSplit` from application settings. Split into two is the default. A note whose source frames strictly contain the split becomes two notes: the original ID stays on the first clip, and the new note starts at the split. Preserve first keeps only the first part. Notes that do not cross stay whole on the side that contains them. Non-looping MIDI keeps its stretch and source window. It writes a separate pattern for a piece only when a note crosses, so other clips that share the original pattern are unchanged. A looping clip writes two new unlooped patterns from the notes heard on each side, so repetitions that do not cross the playhead stay intact. Application settings store the choice as `midi_note_split` (`split` or `preserve_first`). A missing or unknown value means Split into two.

The Edit command is disabled without a selected clip, when no selected clip contains the playhead, and outside Timeline and Editor. The context item is disabled when none of its target clips contain the playhead. Both resulting clips are selected. Undo restores the split in one step.

### Time range

Command-drag on macOS, or Ctrl-drag on Windows and Linux, selects one time span on the lanes the drag rectangle crosses. The pointer uses `CursorIcon::Crosshair`, the same cursor as creating a loop range, while that gesture is available and while the span is being drawn. Clip edges keep their resize cursor unless Command starts a span. The span is UI state. It may include partial clips, several clips, and silence. On macOS, Command always starts a new span. On Windows and Linux, Ctrl-drag that starts inside an existing span moves or duplicates it; Ctrl-drag elsewhere starts a new span. Option-drag on macOS, or Ctrl-drag on Windows and Linux that starts inside the span, duplicates it. The modifier at release decides.

`Project::clip_range_slices` returns the heard pieces through `Clip::retained_range`. Each piece gets a new ID and keeps its timeline position, source offset, loop phase, stretch, name, and color. `Project::without_clip_range` removes that time and keeps the outside pieces. A non-looping piece advances `source_offset_frame`. A loop uses `ClipLoop::shifted`; a partial cycle unwraps when the retained length fits in the remaining phase. MIDI crops the source window and does not rewrite the shared pattern, so other users of that pattern stay unchanged.

Move clears the source span, then places the pieces with `Project::placed_clips`. Duplicate places them without clearing. Copy stores the pieces with an anchor at the span start so paste at the playhead keeps leading silence and gaps. Delete removes the span. A span that contains only silence clears the highlight and leaves the project unchanged. Zero movement is a no-op. Failure leaves the project unchanged. Snapping uses the project grid; Shift bypasses it. A click outside the span, Escape, undo, redo, or selecting a whole clip clears it. Focus loss cancels an in-progress drag.

All clip gestures share project-grid snapping, Shift bypass, selection snapshots, overlap resolution, staged previews, and release handling. Escape, focus loss, or disabled editing cancels a gesture without publishing source/range changes. No-op releases retain asset identity and the modified state. File actions and view switches are disabled during active gestures. MIDI source resizing retains at least one tick and clamps to project zero and supported tick/frame bounds. Audio trims retain their source limits and shared-boundary behavior.

### New tracks for clip copies

Duplicating clips into empty Timeline track space creates fresh tracks of the matching audio or MIDI type. Group paste uses the same rule when it needs more tracks. Use the standard new-track name, color, 0 dB gain, centered pan, mute/solo off, and no effects. A new MIDI track starts with one empty instrument layer; it does not inherit the source instrument, Sampler, modulation, or Main bus settings. It remains silent until a source is installed. Existing destination tracks retain their settings.

Copies receive new clip IDs and retain their asset, name, source range, loop, stretch, and color override. Group track gaps remain intact. Previews do not create saved tracks; drag release publishes tracks and clips together. Cancellation or invalid placement leaves the project unchanged. Ordinary moves into new track space retain the source MIDI instrument. The explicit Duplicate track action still copies track settings without clips.

## Model and ownership

- `TrackKind` defaults to Audio for older manifests. MIDI tracks own one versioned instrument with parallel layers, each containing independently configured oscillators and an optional amplitude envelope; audio tracks reject source instruments in core validation.
- MIDI patterns are embedded assets with stable source IDs. Notes have stable IDs, pitch, velocity, start ticks, and duration ticks. One beat is 960 ticks. New patterns default to 960 ticks (one beat).
- Clip frame ranges, source offsets, repeat bases/phases, and stretch ratios stay separate from pattern content. Pattern edits create a new asset and update only the edited clip's source reference. Other clips and clipboard copies retain the original asset. No-op edits retain the source ID.
- Source resizing creates a new asset for the edited clip and commits note, range, and neighbor changes together. Full-source clips follow the new source length. Trimmed clip ranges, repeat bases, and looped arrangement lengths follow the same duration change within source bounds. Clamp offsets and repeat phases to the new source bounds and preserve stretch. Resizing a looped source changes its repeat spacing; source edits remain shared across that clip’s visible repetitions. Group source resizes prepare every candidate from the original project, then resolve all neighbor trims/removals once. Right edges give earlier clips priority; left edges give later clips priority. Other source users retain the previous pattern.
- Saving includes pattern data and instrument settings in `project.json`. MIDI assets have no file path and are excluded from external-file resolution and overwrite checks. Source recordings remain external references.
- Tempo changes scale MIDI clip starts, durations, offsets, repeats, and derived source-frame bounds. Note ticks stay fixed. Audio clip durations stay fixed. The whole tempo change rejects overlaps, invalid ranges, or overflow atomically.
- Processing-rate changes retain note ticks and musical timing, rescale clip ranges, and rebuild the prepared voices through the existing session replacement path.

## Shared units and rendering

`daw-unit-core` defines backend-independent descriptors, typed ports, versioned oscillator and instrument settings, processing context, and the prepared mono source lifecycle. Instrument version 3 stores ordered stable-ID layers with names, source lists, generic Envelope instances, and optional Amplitude settings with explicit connections. At least one layer is required, and layer IDs must be unique within the instrument. Empty source lists are valid and render silence. New MIDI tracks start with one empty layer and no installed envelope. Version 1 flat and collection instruments migrate into Layer 1, with their sources and envelope settings intact. A missing legacy envelope retains the previous short gate. Oscillator and envelope unit versions remain unchanged. Each oscillator saves its mute state; missing mute fields default to false, including legacy single-oscillator settings. Validate every source before committing a change. `daw-oscillator` implements that lifecycle with FunDSP. Neither crate depends on the DAW model, UI, or devices. Standalone tools can reuse this source contract; no standalone app is included yet.

The engine prepares note schedules, oscillator state, and voice slots before publication. Events use project sample frames. At a shared frame, note-offs precede note-ons; simultaneous note-ons sort by stable note ID. Each simultaneous note has independent oscillator and envelope state in every layer. All layers receive the same note events. Source gain and pitch changes retain 5 ms parameter ramps. Each source applies its own waveform, pitch, and gain. Muted sources continue advancing with zero output. Sum sources within each layer without automatic normalization, apply that layer’s envelope, then sum all layers and apply note velocity before track processing. An absent envelope uses the legacy linear 5 ms attack/release gate, zero Decay, and 100% Sustain. Empty layers contribute zero. Prepare voice slots with capacity for the supported 10 s release range, adjusted for clip stretching, so live release edits cannot steal tails or allocate; reuse slots once those tails end. There is no fixed voice cap or runtime voice stealing. Note-offs affect only their assigned note. Slots never allocate during audio processing.

Seek resets oscillator voices and reconstructs held notes, ADSR stages, and release progress at the new position in project time, including stretched and trimmed clips. Stop resets voices; pause preserves voice state. Clip/repeat/transport-loop boundaries end the previous note. Mute/solo suppress output while voices keep advancing. Mixer gain/pan and oscillator gain/pitch/mute changes transfer compatible voice state without callback allocation. Oscillator gain and mute changes use 5 ms amplitude ramps; pitch changes use 5 ms frequency ramps. These changes preserve phase, held notes, and envelope progress, including when a new change arrives during a ramp. These changes retain any existing transport transition instead of restarting it. Waveform, layer/source-count, envelope-presence, and pattern changes publish new prepared state with the existing output transition. The control is named Pitch; the saved `transpose` field remains unchanged for project compatibility.

Clip gain and transpose belong to the clip, not the pattern. Playback multiplies MIDI output by the active clip’s linear gain before Main gain. Transpose is added to each note-on pitch and clamped to MIDI 0–127. The saved pattern stays unchanged. See [Clip settings](../editing/clip-settings.md).

Playback and WAV/MP3 export share sequential oscillator processing, note timing, clip fades, and mixer behavior. Export renders the arrangement once without transport looping or playback start/pause ramps. `RenderPlan::sample_at` and `render` remain prepared-audio lookup APIs; use `Renderer::render_offline` for mixed audio/MIDI rendering.

The Layers column in Instrument matches the Tracks panel’s 250-point width. Its left-aligned title and Plus button sit above layer headers in that column; empty space to their right uses the workspace background. The column retains the panel background below its rows. Each layer header uses the shared `icons::header_icon` Audio Waveform artwork and regular 13-point name text. Drag the icon, name, or unused layer-header space to reorder layers. Mixing controls and the active name editor keep their own gestures. All drag areas reuse one layer drag handler; the insertion line previews the destination, and viewport edges scroll the rows. Option on macOS or Ctrl on Windows/Linux switches the same gesture to duplication; the modifier at release chooses move or copy. Copy mode shows the Copy cursor and an insertion line even beside the original. Drag activation reuses `drag::press_origin` and `drag::crossed_threshold`, including fast motion/release in one frame; previews do not create identities or settings. Release commits one `Edit::SetInstrument` through the existing history and preparation path. Escape, focus loss, disabled editing, invalidated layer order, or an outside drop cancels. Output is outside the target viewport and cannot be copied. Double-click a name to select and edit it; Enter saves a trimmed, nonempty name. Escape/focus loss and track/view/project changes cancel. No-op moves and unchanged or empty names do not mark the project modified. Names and row order persist with the layer ID and its source/envelope settings. Older version-2 instruments without names receive Layer N names from their saved positions. Instrument configures MIDI tracks only. Its playback-toolbar dropdown excludes audio tracks; selecting an audio track elsewhere leaves Instrument at its MIDI selection prompt. Effects is a separate view with a shared track selector for audio and MIDI tracks. It owns track effects and currently reports that effect processing is unavailable. Instrument sources and layer envelopes stay in Instrument. Both processing views preserve clip selection and project data when switching tracks. ## Envelope unit

When installed, Envelope appears to the right of Oscillator within its layer. It can also be added before a source. Both panels use the shared unit shell and have equal height, aligned unit headers and three control rows, with one full-height, 1-point divider between them in the same color as their outer borders. All units scroll horizontally together. One leading 90-point strip stacks the Timing knob in row one and the Mode dropdown in row two, with an empty third row. The four ADSR stage strips follow it. All five strips have the shared internal padding and full-height separators; their bottom labels align with oscillator Power buttons. The unit keeps the shared 244-point height. Mode no longer occupies the header. LFO controls are unchanged.

Timing selects **Time** (default) or **Note** with the shared bounded two-way knob. Mode retains its compact dropdown for **Per note / Retrigger / Legato**, below Timing in the same column. On Main, or when the Envelope feeds a shared destination such as an LFO or track effect, Mode disables **Per note** and permits **Retrigger / Legato**. Header power and collapse remain independent.

In Time timing, Attack and Decay retain their millisecond controls. In Note timing, they each span 0–100% of the triggering note's full duration, in one-percentage-point steps. The initial Note values are 100% Attack and 0% Decay. Each timing keeps its own values when switched. Sustain remains a level and Release always uses milliseconds. Attack and Decay percentages are independent: if their sum exceeds 100%, note-off interrupts the unfinished stage and starts Release from its current level.

Per note resolves duration independently for each voice. Retrigger restarts on each note-on and uses that note's length. Legato uses the first held note's length; overlapping notes neither restart nor rescale it. Shared modes release only after the final held note ends. Note-off precedes note-on at a shared boundary. The host prepares full note lengths in processing-rate frames, including MIDI stretch, before playback. Trimming, seeking, and repeats reconstruct progress from the original note start; they do not fit the envelope to the remaining visible clip. A host with an unknown live-note duration uses the retained Time values rather than predicting note-off.

The reusable `daw-envelope` crate produces a 0–1 modulation signal. ## Current limits and follow-up work

The accepted [source-container architecture](../architecture/modular-audio-units.md#one-source-container-per-track) gives each MIDI track one instrument containing reusable oscillator units, modulators, and internal processing. The instrument owns routing and note/voice allocation and exposes one output bus to track effects and gain/pan. The current instrument supports parallel layers with oscillator sources, generic Envelope modulators, and an optional Amplitude stage. Oscillator Pitch/Gain, Amplitude, Auto-filter, and Drive own typed modulation connections. The Oscillator module implements multiple sources with a summed output. Layer outputs sum into the track’s single instrument bus. Independent shared [LFO components](lfo.md) also use the same source and destination contract. Internal effects and user-defined graph routing remain planned.

- Pattern length starts at one beat. Body edges resize its source; header edges loop the visible range. Both gestures work in Timeline and the Editor track strip.
- One oscillator instrument per MIDI track, containing one or more layers, zero or more oscillator sources per layer, and multiple voices for polyphonic patterns. Oscillator frequencies at or above the processing Nyquist limit render silence. No MIDI file import/export, hardware MIDI, live note input, audition keyboard, or note clipboard yet.
- No audio/beat editor, effect chain, graph connections, saved graph layouts, missing-unit fallback, or standalone interface yet. The larger [Units design](../architecture/modular-audio-units.md) remains the source for that scope.
- Native device stability and the full eight-voice workload with representative effects require separate validation. Automated rendering and input tests do not establish device or cross-platform behavior.


Modulation uses the [shared portable source and destination contract](../modulation/contract.md). Source lookup, scope checks, typed route evaluation, and common smoothing belong to `unit-core`; the unit retains its audio processing and final parameter bounds.


## Instrument Main bus — 2026-10-16

The [Main bus](main.md) is fixed below the scrolling layers. It receives their stereo sum, applies independent gain/pan before track effects, and hosts shared Envelope/LFO components through the existing catalog, controls, and modulation contract. It starts compact, keeps its own saved row/unit presentation, and cannot be removed or reordered. Missing Main data migrates to neutral settings without changing old audio.

Each oscillator has a stable ID and individual [Pitch and Gain modulation targets](../modulation/oscillator-pitch.md). Its routes use per-note or shared Envelope/LFO values through the shared destination interface. Pitch amounts use signed fractional semitones; Gain amounts use signed dB. Base transpose/gain and waveform phase remain independent of modulation.

## Sampler layer sources — 2026-10-17

A regular instrument layer can use [Sampler](sampler.md) instead of Oscillator. MIDI notes trigger independent stereo sample voices relative to the root note across the full MIDI 0–127 range. MIDI velocity and the existing Amplitude stage shape their output. One-shot continues the source after note-off; Gate follows the note gate/release. Clip boundaries and transport retain their existing behavior. Root note is the saved unshifted MIDI pitch, with the same C−1–G9 names as the piano roll. Existing oscillator layers retain their sound and source lists.
