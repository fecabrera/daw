# Sampler source

Implementation requirements and design records. For user instructions, see the [user guide](../../docs/instruments/sampler.md).

Implemented design, updated 2026-10-18. Sampler is an instrument component for regular MIDI layers. It plays a selected mono/stereo region at the MIDI note's pitch relative to its saved root note, with offline preparation through the selected project engine. See the [acceptance requirements](../architecture/iteration-1.md#sampler-source--2026-10-17) and [validation record](../validation/README.md).

## Placement and source ownership

The [saved-cache and background-preparation plan](../architecture/background-audio-preparation.md) proposes persistent pitch buffers and nonblocking MIDI edits. The preparation/publication rules below describe current behavior until those stages are implemented.

Register Sampler once in the Instrument components catalog. A layer can have one of Oscillator, Sampler, or [Granulizer](granulizer.md); the Oscillator component can still contain multiple oscillator strips. Empty layers remain silent. Sampler stays first in the layer and cannot enter Main. Conflicting catalog additions and installed transfers leave the project unchanged and show an unsupported-target hint. A catalog selection containing multiple source types cannot enter a regular layer.

Source headers offer an explicit **Replace source** action. Replacement keeps the layer's identity, mix settings, modulators, and Amplitude stage. It discards the old source settings and oscillator pitch routes when applicable. Component selection, Delete/Backspace, header group moves/copies, focus, insertion previews, and cancellation reuse the existing component paths. Sampler copies receive a fresh sampler ID and share the immutable audio asset. Removing Sampler discards its settings; retained Envelope/LFO/Macro/Amplitude settings keep their existing restoration rules.

## Loading and selecting audio

1. Add Sampler to an empty regular layer, or replace its Oscillator component through the header menu.
2. Drop one supported WAV, MP3, or AAC-LC file onto the unit, or select Choose sample from its preview or header menu. File decoding, project-rate conversion, and waveform preparation use the existing media/worker path. Supported codecs, containers and channel limits match [ordinary import](../audio/import.md).
3. To use a timeline audio clip, drag it over the Instrument view button. This opens Instrument on the first MIDI track with a Sampler. Drop onto that unit. The original timeline clip stays in place. The sampler retains its source trim, repeat length/phase, and existing stretch mapping; track gain, pan, and effects are not captured.
4. Drag the preview's selection-bar edges to resize the region, its body to move it, or outside the current region to create another region. Shift bypasses the shared musical-grid/source-boundary snapping. Preview during the gesture; commit only on release. Escape, focus loss, or disabled editing cancels it.

The source initially spans the full file or visible dropped clip. Selection uses integer frames on that input's local clock and never changes the recording or project loop selection. The filename is inside the clip header, using the common clip-header painter. Mono/stereo peaks reuse the Timeline waveform painter. The preview shows the standard bar/beat ruler and grid, including zoom-dependent subdivisions, through the same painters as Timeline and Editor. Its clock starts at local frame zero and uses the effective playback duration at project tempo/rate. Off uses the original input clock. Time/Bars scale the full preview by the selected region's prepared output/input ratio: a one-bar target spans one bar across that region, including when the region is only part of the file. The grid adapts to duration, tempo, mode, and committed selection changes; arrangement scroll/zoom stays independent. Grid lines span both waveform channels. Selection snapping maps through the same ratio back to input frames, with Shift retaining free movement. The selection bar shares the project loop ruler's painting, colors, handles, and hit geometry; it selects playback content without enabling repetition. A read-only marker shows an actual active voice position through prepared atomic telemetry. With overlapping notes, it shows the furthest active position. No UI clock advances playback.

Dropping a replacement resets selection to the new full input. An explicitly set Time/Bars target remains unchanged. Loading, region changes, and duration changes publish the new project and prepared audio together. Failure or Cancel retains the previous settings, sample, and playback. Missing external files retain the saved input and display a missing-source state, with silent rendering. Shortened files supply silence for unavailable ranges. Save and Save As preserve external references; they do not bundle recordings.

## Controls

| Control | Behavior and defaults |
| --- | --- |
| Gain | Existing marked gain knob, exact silence through +12 dB; default 0 dB. Reuse pointer/keyboard handling, Shift sensitivity, unity mark, and double-click reset. Gain and unit power ramp over 5 ms. Accept Envelope, LFO, and Macro modulation through the shared destination API. |
| Stretch mode | Standard dropdown in the duration group: **Off / Time (ms) / Bars**, default Off. The closed selector shows Off, ms, or bars. It stays visible in expanded units, including Off. There is no separate stretch-mode knob. |
| Duration | Always shown in expanded units. Off displays the original selected duration in milliseconds as a disabled numeric readout (0 before loading). Time/Bars use the standard drag/numeric input, milliseconds or whole four-beat bars. Bars has a minimum of 1 and stable 1-bar drag steps, including with Shift. Switching to Bars rounds the current output duration to the nearest whole bar, with a minimum of 1. Switching to Time preserves the current output duration. Selection changes retain an explicit target. |
| Trigger | Standard **One-shot / Gate** dropdown beside root note and duration, default One-shot. Reuse the duration selector helper, small text, tooltip, and accessibility metadata. |
| Root note | Note-name input and adjacent sharp toggle; default C4 (MIDI 60). Use the same C−1–G9 naming/range as the piano roll. Drag the box through MIDI notes in semitone steps (10 points per step; Shift slows adjustment tenfold). The sharp toggle follows accidental crossings. Preview while dragging and commit on release; Escape, focus loss, or disabled editing cancels the drag. Click the box to type. The box accepts natural names such as A3/B2/C4, with the octave in the same input. The separate sharp toggle supplies the accidental. Disable sharp for E, B, and out-of-range combinations such as G9. Enter or focus loss commits valid text; Escape or invalid text retains the previous note. Root note defines the unshifted MIDI pitch. Changing it uses the prepared-audio transaction below. |

Off preserves the selected input duration. Time stretches to a fixed number of milliseconds, independent of tempo. Bars stretches to a musical duration that follows project tempo. Duration and MIDI pitch are independent through the saved project stretch backend/revision. Round the output length to the nearest project sample frame. Require a positive output length and a duration ratio within 1/8–8 of the selected region; reject the complete edit otherwise. Time accepts positive finite milliseconds; Bars stores positive whole bars; project validation applies these frame/ratio bounds. Before loading audio, Time defaults to 1000 ms and Bars to 1 bar. First load initializes Time from the original input duration and Bars from its nearest whole-bar duration, with a minimum of 1. Saved fractional-bar prototype values round to the nearest whole bar on load, with a minimum of 1; output frame/ratio validation still applies.

One-shot keeps the source running to the selected region's end after MIDI note-off. Gate follows the existing note gate and Amplitude release behavior. Trigger changes apply to new notes; existing notes keep their trigger behavior. Neither mode repeats the selected region. Existing Amplitude modulation can shape or silence either source, and MIDI velocity scales each voice. Both modes stop at the source end and follow existing clip/loop/transport boundaries. The signed semitone offset is MIDI pitch minus root note. Offsets in −127..=127 select prepared variants, covering every MIDI note/root pair. Stereo channels retain their relationship through the same Amplitude factor, layer mix, Main, and track effects. Boundary fades are 5 ms.

Root note and the sharp toggle form one joined input group, with a shared outline and internal divider. Match its full outer height, including the border, to the standard 22-point duration input in display and text-entry states. Use the shared 11-point numeric font for the root note, sharp toggle, duration value, and dropdowns. Duration is a second joined input group: a centered drag/text value and a separate Off/ms/bars mode dropdown, with one outline and internal divider. Keep its full width fixed at 120 points, including a 60-point mode segment, in display and text-entry states. Scale only an unusually long duration value below 11 points when needed to fit the numeric segment. The dropdown remains visible while editing and owns stretch-mode changes. With no pending value edit, opening it, cancelling it, or selecting the current mode leaves the project clean. Stretch-mode changes use the existing instrument edit and worker preparation; errors retain the current settings/audio. Trigger changes use the same instrument edit without rebuilding prepared audio. Opening, cancelling, or selecting the current Trigger choice leaves the project clean. Both retain their separate drag/text and toggle interactions. The root-note group, duration group, and 76-point Trigger dropdown share one horizontal row below the preview, with 4-point gaps. All controls have the same 22-point outer height. Omit visible Root note and Duration labels; retain tooltips, accessible names, and duration mode names. Gain occupies the first row of one standard 90-point strip, including the shared padding. Center the Sample label in the bottom footer row, aligned with the other unit footers. Reserve the two remaining control rows to keep the standard footer position. A shared full-height divider separates this strip from the waveform section. The shared unit shell owns power, collapse, selection, and header behavior. Compact layers retain the source name/footer and hide waveform/controls; horizontal collapse hides the body. Both retain a sample drop target. Expanded layers retain their existing height. Parameters remain editable while the unit is off; muted sources keep advancing.

## Architecture and saved state

`unit-core` owns version-1 `SamplerSettings`, `SamplerInput`, trigger/mode enums, shared clip repeat/stretch value types, MIDI note naming, and the portable `StereoSourceUnit` contract. Optional layer `sampler` defaults to absent and retains instrument version 3. Old oscillator-only instruments retain their source lists and sound. Core validates source exclusivity, supported audio assets, positive bounded ranges, durations, note range, finite gain, unique sampler IDs, and transfers atomically. Project-rate changes rescale selection/input/repeat frame coordinates with the existing checked arithmetic; Time and Bars retain their units.

`crates/sampler` owns allocation-free stereo playback, local position, gain/power ramps, and boundary fades. It has no project, UI, media, or device dependency. The host supplies an immutable bank of prepared stereo buffers indexed by MIDI note and note triggers. `crates/project` composes the retained clip mapping and selected region, then prepares its duration and pitch variants through the existing stretch cache/backend. Root output retains the unique sampler ID in the render plan's audio map for preview and duration lookup. A separate prepared Sampler map holds the variants; original assets keep their own IDs and buffers. Only workers prepare or replace those buffers.

The shared MIDI runtime owns voice allocation, note timing, seek reconstruction, looping, velocity, and Amplitude modulation. It advances Amplitude once per layer/voice and applies the resolved gain to both stereo channels. Existing oscillator arithmetic remains unchanged. Compatible Gain/power/presentation edits retain sample positions and in-flight ramps without callback allocations or final-owner retirement. Content/duration/root replacements use the existing prepared-renderer transition and note-age reconstruction. Pause retains positions; Stop/seek use existing transport resets. Live playback and offline export share this path.

Sampler publishes no modulation source. Gain consumes the [shared source/destination contract](../modulation/contract.md) as described below. Pitch, duration, root note, selection, and Trigger do not accept modulation. Reverse playback, internal looping, slicing, automatic pitch/tempo detection, multisampling, and live pitch modulation remain outside this version.

## Offline note pitch — 2026-10-18

The shared `SamplerSettings::pitch_offset` maps MIDI 0–127 to a signed offset from the saved root (default C4/MIDI 60). Accept −127..=127 inclusively, covering the full MIDI range. Invalid MIDI values or unavailable entries are silent, without clamping or substituting the original pitch. Root audio stays sample-exact at duration ratio 1. The existing settings version and manifest fields remain unchanged. Older projects now interpret their saved root note as pitch rather than descriptive metadata; this intentionally changes non-root Sampler notes.

`Session::prepare_stretches_cancellable` collects unique pitches from patterns referenced by each Sampler track, including notes outside the visible clip range. Prepare root audio plus required supported offsets, at most 128 variants. Do not prepare all MIDI pitches on sample load. Empty tracks need only root audio. Each variant starts from the same selected region after retained clip trim/repeat/stretch mapping; never shift a previous note variant. Root changes can reuse matching offsets. Missing recordings keep empty/silent banks.

`daw-media::PreparedSampler` retains selected-region identity (source allocation, rate, input mapping and selection) and a sorted offset-to-`PreparedStretch` map. Reuse a variant only when source, rate, exact duration ratio, selected engine/revision, pitch and pitch revision match. `PreparedStretch::with_pitch_cancellable` dispatches to `Request::with_pitch` for Integrated and uses the same bounded pitch-pass schedule with the existing offline linked-stereo R3 adapter. Each pass receives its `2^(semitones/12)` factor; duration changes apply only in the first pass. Final duration is identical for every note. Source identity retains its allocation so pointer reuse cannot cause a false cache hit. Prepared PCM and known scratch use shared memory admission. Integrated pitch exposes its own working-memory estimate, so the adapter reserves private intermediate/filter storage without duplicating those calculations. Native processor scratch remains library-owned; the budget is not a process RSS guarantee.

Root, MIDI pattern, sample, selection, duration, tempo, rate, and engine changes must prepare missing variants before publication. Reuse the cancellable worker path for ordinary edits, pasted clips, cross-track moves and duplication. Successful jobs publish the project, root buffer, bank and any placement selection together. Failed or cancelled jobs retain the previous session, selection and playback; completed intermediate variants are discarded. Reopening, Save As, export and processing-setting changes use the same preparation path. Variant buffers are transient and are never serialized or written into the source recording.

The engine builds one shared `SampleBank` per layer outside the callback. Each voice owns that immutable bank and selects its note index at note-on; it never replaces a last-owner audio pointer during playback. Missing entries return silence. Note scheduling, polyphony, velocity, note-age reconstruction, seek/loop handling, One-shot/Gate, boundary fades, gain modulation, telemetry and live/export mixing remain shared. Runtime compatibility includes root note and root PCM identity, but excludes the prepared pitch-variant set. Root/content changes reconstruct active notes through the existing renderer transition; gain, power, route and presentation edits retain positions and smoothing. All pitches use the same duration, so the existing preview position and source-end logic remain valid.

Acceptance: verify root identity, ±12/±24 and wider pitches, full MIDI endpoints, exact duration for Off/Time/Bars, all processing rates, engine switching without fallback, linked stereo, independent overlapping notes, live/offline/seek parity, float WAV export, save/reopen, cache reuse, root/note invalidation, worker cancellation and failure retention, paste preparation, and callback allocation checks. Native listening, device interaction and other platforms require separate checks.

## Gain modulation — 2026-10-17

Sampler Gain is a per-note destination. Connect any compatible Envelope, LFO, or Macro from the same MIDI instrument, including shared sources in Main. Per note Envelopes supply independent voice values; Retrigger/Legato Envelopes, LFOs, and Macros supply shared values. Gain modulation changes level without changing the trigger or note-release ownership. One-shot/Gate, source end, Amplitude, and transport retain their existing lifecycle rules.

| Parameter | Saved amount | Processing |
| --- | --- | --- |
| Gain (`SamplerGain`) | Signed −24 to +24 dB per connection; zero is neutral. | Sum the source values times their amounts and enable weights through the common resolver. Smooth the additive offset over 1 ms, limit the sum to ±96 dB, multiply the ramped base gain by `10^(offset / 20)`, and cap the result at +12 dB. Exact base silence and unit power-off remain silent. |

Sampler settings and portable DSP declare the same parameter and PerNote scope through `ModulationDestinationSettings` and `ModulationDestination`. The host prepares one route vector per voice and invokes `process_modulation`; it never adds another source lookup or route loop. Sources advance once per sample and publish cached values for fan-out. Route amount/power and source enable changes retain the common 5 ms ramps. Gain and unit power keep their existing 5 ms base ramp. With no effective route, audio remains sample-exact with the unmodulated path. Both stereo channels receive the same gain before boundary fades, velocity, Amplitude, and layer mixing. Standalone `next_sample()` remains the neutral-input adapter.

Use the shared secondary-color header dot to expand connection strips on the right. The strips reuse Source/Destination selectors, destination-matched signed Gain amount knobs, Power, removal, Plus, and route reordering. New connections are unassigned, enabled, and at zero amount. The Gain knob retains its base pointer/readout and adds the standard assignment dot, source/amount tooltip, possible-range arc, and click-to-open action. Two moving dots show the lowest and highest active voice gain in dB, including base/power smoothing and excluding boundary fades, velocity, Amplitude, and voice summing. The prepared atomic snapshot retains playback position in slot 0 and adds those gain extrema in slots 1/2; unavailable values are NaN. The UI never advances or estimates DSP.

Sampler settings version 1 adds optional `modulations` and `modulation_open`, defaulting to empty and closed in older projects; instrument version 3 is unchanged. Validate supported parameters, finite bounded amounts, unique route IDs, ordinary untargeted routes, and source references in the same instrument. Invalid edits fail atomically. Save/reopen, Save As, processing-rate changes, track duplication, and component moves/copies preserve routing and visibility. Sampler copies receive fresh route IDs and retain source assignments. Provider moves remap Sampler consumers through the common core transfer path. Removing or replacing Sampler removes its routes.

Compatible Gain, route, power, and presentation edits retain sample positions, held notes, offset smoothing, and route history by stable identity. They do not rebuild prepared audio. Reset clears offset history and resets routes to their current targets. All route storage and snapshots are prepared outside the audio callback; processing, publication, and retargeting allocate nothing and perform no locking or file I/O. Playback and export share this path.

## Live MIDI pitch dragging

The editor can bend a running note before its new offline pitch variant is prepared. Preserve the fractional sample cursor, gain and modulation smoother; linearly interpolate the current buffer at the new pitch ratio with a five-millisecond ratio ramp. Measure start/end boundary fades in output time during the bend. This transient bend changes playback speed. Cancellation returns to the original pitch. Do not restart ended samples.

On pitch-only publication, swap immutable prepared banks between playing and retired sources without releasing final owners on the callback. Select the committed pitch buffer at the current cursor, crossfade changed PCM for five milliseconds (including replacements at the same pitch index), and ramp the residual rate ratio back to unity. New notes use the committed prepared buffer normally. Other compatible bank updates preserve positions. Worker failure leaves the old bank and written pitch intact. The saved project and export use prepared constant-duration pitches, never transient editor input.
