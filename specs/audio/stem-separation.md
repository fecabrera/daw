# Stem separation

## Accepted behavior

Timeline's audio-clip context menu contains **Stem-separation**. It acts on the clicked clip, independently of a multi-clip selection. Require a configured local CPU model; saved and unsaved projects are supported. The menu and action share one readiness guard without a save-folder prerequisite. Do not bundle, fetch, or redistribute weights. Store machine-local model paths in application Settings, outside the project manifest.

The arranged clip is the input: resolve the shared prepared buffer for the saved stretch engine/revision and transpose, then map trim and repeat coordinates through `Clip::source_frame`. Apply the shared loop-seam fade. Exclude outer fades from the input because normal stem playback supplies them. Do not bake clip gain, track/group/Master mix settings, effects, or modulation. Copy clip gain to each resulting stem.

Publish a new processing group and four ordinary audio tracks, in Drums/Bass/Other/Vocals order, at the end of the track list. Start each stem at the original clip start and retain its exact project-frame duration. Retain the original clip's ID and all settings; set only its saved `muted` field. Use one history publication. Generated tracks use normal track mix defaults and shared group processing.

## Stages and ownership

| Stage | Owner | Contract |
| --- | --- | --- |
| Menu and configuration | `daw-ui` | Existing file-action/job/dialog guards; local ONNX pickers; no inference in painting |
| Snapshot and scheduling | Existing UI `run_job` | Clone Session through shared immutable audio owners; one offline job; keep playback/session on failure |
| Input preparation | `daw-project` | Shared clip-buffer lookup and frame mapping; shared loop fade; cancellable shared resampling to stereo 44.1 kHz |
| Model and separation | `daw-separation` | Pinned Charon revision; private backend types; stream source and output callbacks; finite stereo PCM |
| Encoding | Shared `daw-media::WavEncoder` | Float32 WAV; four fixed safe names; ordered blocks; validate exact model-rate output length |
| Project-rate preparation | `daw-project` + media | Decode/resample through shared media code; require the exact ceiling-rounded model-to-project frame count, then trim only the known round-trip surplus to the original duration; encode project-rate Float32 and prepare peaks |
| Import and transaction | `Session::import_decoded`, core edits | New stable IDs, one new track per stem; `GroupTracks` and `SetClipMuted`; validate before publication |
| Publication | UI worker polling | Recheck cancellation, retain current navigation, replace session once and call shared history/render synchronization |
| Status | Shared `job_report` | Same dialog, progress, diagnostics, and completion rules as export; cancel requests an atomic flag |

The separation crate has no UI/device dependency. Dependencies flow project → separation → media. Decoding, model construction, inference, WAV I/O, peaks, and resampling stay on the existing worker. Nothing is added to the audio callback.

Charon runs windows in its existing serial stream pipeline. The adapter retains only one output block per write, not four whole model-rate output arrays. The arranged input and resampled input still need memory; imported project-rate buffers and peaks use the normal shared media path. There is no streaming disk-backed project audio or fixed job-memory guarantee.

## Backends

Retain Charon revision `bc045cd80f009ea863772c5afef15928101df66f` (0.1.2 source version) and the lockfile. Cargo overrides that Git source with `vendor/charon-audio`; its [patch record](../../vendor/charon-audio/DAW-PATCH.md) identifies the source and the provider-policy compatibility change. Reset ort’s automatic device policy before registering explicit CPU/CoreML providers, so a CPU-only model cannot silently select CoreML. Keep Charon’s processing and low-memory presets unchanged. Default features are disabled; enable the ONNX backend on supported targets and CoreML only on Apple Silicon macOS. Intel macOS builds omit Charon, ort and their native runtime; shared model/progress types remain available, while the project API returns an unsupported-target error before preparation. Settings and the clip menu use shared target availability to disable separation controls with an explanation. Desktop and CLI builds remain available. The default HTDemucs CPU preset uses its in-graph model and low-memory configuration. The optional macOS preset uses the split-transform ONNX model with CoreML CPUAndGPU compute units. CoreML is an execution provider, not a promise that every operation runs on a GPU. ONNX Runtime can assign unsupported nodes to CPU.

Pin the workspace `ort-sys` patch to upstream revision `f2a5f73c9dd9ff3682303481cc792bf4669e3e94`. It retains the `2.0.0-rc.13` binding version used by Charon, while selecting checksum-pinned ONNX Runtime 1.31.0 artifacts containing the model-loading bounds check from upstream [#32609](https://github.com/microsoft/onnxruntime/pull/32609). Runtime 1.30.0 still lacks that check. Keep runtime notices aligned with 1.31.0. A synthetic malformed Loop test runs in a separate process, checks the linked runtime version, and requires the specific clean-rejection error.

On Apple Silicon macOS, the separation crate's build script resolves Apple Clang's compiler runtime through `xcrun` and links `libclang_rt.osx.a`. Static CoreML objects use its platform-availability helper; Rust's native link does not add that library automatically. Keep this prerequisite in the backend crate so desktop, CLI, and tests share it, including thin-LTO release links. Intel macOS and other targets skip this step.

On a CoreML load, inference, or output-validation error, discard its writers and retry using the separate CPU model and fresh files. Retain a warning. Do not retry a cancellation. Both paths validate stem identities/order, channel count, rate, finite samples, and exact model-rate duration. Whole-process termination or native out-of-memory abort cannot be recovered in-process.

Compiled CoreML data lives under the user cache directory's `DAW/Charon/CoreML/ort-1.31` subtree, keyed by Charon's model-content hash. It is separate from project stems, model locations, and seek caches. Models are loaded per job; a resident model service is not implemented. Cold load can dominate elapsed time. See the [CPU evaluation](stem-separation-evaluation.md) and [CoreML evaluation](stem-separation-coreml-evaluation.md); their timing evidence is not a feature-level latency guarantee.

The shared report uses the platform-neutral loading message “Preparing audio and loading model…”. Do not mention CoreML compilation in this message because Windows, Linux, and CPU-only macOS jobs do not use CoreML. The shared report progress bar fills the available dialog content width. Retain the dialog's existing left and right padding for separation and export reports.

## Files, failure, and persistence

Reserve a portable `stems/<clip name>/` directory with `create_dir`, adding a numeric suffix on collision. Bound the final basename to 255 UTF-8 bytes, including the suffix; truncate only at character boundaries. Use the same reservation for separation and generated-source copies. Never overwrite a pre-existing output directory or source file. Only the job's reserved directory can be removed on failure. An unpublished `PreparedSeparation` owns that directory and removes it on drop, including when the worker receiver disappears. Successful UI publication transfers file ownership to the session. Undo retains those files for Redo; no orphan-file cleaner is introduced. History restoration retargets generated sources by stable asset ID to the latest saved stem locations, so Save As followed by Undo/Redo retains the copied files.

On successful save completion, shared `SessionHistory::mark_saved` resolves the written session's source paths and updates matching generated assets in current, pending, Undo, and Redo snapshots by stable ID. A later save that omits those assets retains the locations already stored in history. The saved-project dirty-state baseline stays separate from these retained locations. Recalculate snapshot memory and enforce the existing history byte limit after retargeting; do not keep an unbounded relocation map. Failed saves do not retarget history. Blocking save completion must call `mark_saved` before recording the returned session, so source relocation alone preserves Redo and adds no Undo entry. A real project-name change still records an edit. Regression coverage must include this UI completion order with an existing undone mix edit, both unchanged and changed project names, Save As → undo separation → Save → redo separation, removal of the original project folder, and successful Save/reopen of the destination.

Ordinary Save returns its successfully written `Session` from the snapshot worker. Completion uses shared `Session::retarget_generated_sources` for the live session and `SessionHistory::mark_saved` for retained snapshots. Both use the same generated-source merge by stable asset ID and prune temporary owners after their paths move. Keep newer edits, pending history gestures, transport, prepared audio and the existing save/navigation revision guards. Do not replace the live session or record a source relocation as an edit. Cover first Save and same-name Save As with separation undone, Redo, ordinary Save during newer edits and a seek, Undo/Redo after removing the original sources, stable directories on repeated Save, and temporary-owner release.

Unsaved separation reserves a fresh UUID-named directory under the system temporary directory with exclusive `create_dir`, then reuses the normal `stems/<clip name>/` reservation and preparation pipeline. Temporary generated sources use absolute paths and leave `Session.folder` unset. Private shared directory owners travel with session, worker and history clones; unpublished preparation still owns its job directory. Release only directories created by this process, once the last referencing owner is dropped. History snapshots prune unreferenced owners, and save completion prunes them only after successful manifest publication or shared history retargeting. Retained snapshots whose assets were absent from a save keep their temporary owners for Redo. Include temporary-owner metadata in bounded history accounting. Failure or cancellation removes only the new job storage; failed first Save retains the live temporary sources. Closing/discarding the session and its history releases temporary storage. No crash-recovery or stale-directory sweep is introduced.

The status dialog starts with the project stems root or system temporary root and shows the actual output directory after success.

Generated assets use `Source.kind = "generated"` and project-relative paths in saved manifests. Core validation accepts them under the normal audio-source contract. First Save and Save As copy generated assets into reserved directories in the destination project's `stems` tree before publishing the manifest; failed saves remove only newly reserved copies. External recordings remain referenced through existing save behavior. Existing files are never replaced by generated copies. Missing generated sources fail Save As without replacing the manifest.

Shared file publication rejects an existing non-file destination before replacement on every platform. A directory at `project.json` and its contents must remain in place. Failed first Save retains the unsaved session and temporary stems, removes staged stem copies and temporary manifest files, and permits a later successful save.

If `Session::save_new` fails, remove its empty `assets` and `stems` roots before removing the exclusively created project folder. Use non-recursive directory removal so unrelated contents are retained. A generated-copy failure after partial staging must leave the session, original project and sources unchanged and permit the same project name after the missing source is restored.

`Clip.muted` defaults to false for legacy manifests. `SetClipMuted` is a core transaction, undoable and shared by the context-menu Enable/Disable action. Audio random-access and scheduled rendering skip disabled clips. MIDI scheduling excludes them from events and LFO note history. Mute enters source/history fingerprints so renderer/cache inheritance cannot retain stale active schedules. Split pieces preserve the flag. Disabled clips reuse the disabled-unit design: the shared unit header fill, panel-colored body and channels, and secondary text color for names, waveforms, and MIDI notes. The opaque neutral palette follows the current theme and replaces inherited or overridden clip colors while disabled. It does not reduce painter opacity or dim the selection outline.

Cancellation checks input preparation, resampling, streaming reads/writes, model-window callbacks, post-inference preparation, and UI publication. Both post-inference reads use the shared cancellable decoder through packet decoding, resampling, and peak construction. Their preparation helper validates the exact expected model-to-project frame count with shared `media::resampled_frames` ceiling arithmetic, then normalizes to the original duration. Do not use a fixed project-frame tolerance; one model-rate frame can span more than two project frames. Model construction and a native inference call are not interruptible. Both the status-bar and report Cancel buttons set the same atomic flag and retain the job receiver until worker acknowledgement. Cancel leaves the report visible until the worker acknowledges it; failed/cancelled reports require Close. The shared UI modal guards block edits and project replacement while the job/report owns the operation.

## Licenses and validation

Models are user-provided. No rights to distribute pretrained weights are assumed. Keep Charon, ONNX Runtime, and new Rust dependency notices in `crates/separation/assets/licenses`; all three platform packaging paths include them. The runtime binaries are build dependencies, distinct from model weights.

Automated regressions use a deterministic injected separation function to test arrangement/import ownership without requiring models. An ignored opt-in project test exercises real local models and WAV input with `DAW_STEM_CPU_MODEL`, optional `DAW_STEM_COREML_MODEL`, and `DAW_STEM_INPUT`. Never commit weights or test recordings. Executed checks belong in the [validation record](../validation/README.md).

The [native dependency audit](stem-native-dependencies.md) records the exact selected archives, source-derived component inventory, current advisory dispositions, compiler-runtime terms and per-platform packaging requirements. Its ONNX 1.22.0 advisory is a pending remediation item; runtime 1.31.0 alone does not make every transitive component current.
