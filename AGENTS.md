## Communication and scope

- Be concise and pragmatic. Avoid praise, filler, promotional language, and suggestions unrelated to the task. Do not claim formal ASD-STE100 compliance.
- If the request is unclear, confirm the intended behavior before making changes. Resolve routine implementation details within the agreed scope.
- Inspect the code and working tree before editing. Preserve unrelated changes and user data. Keep each change focused; avoid unrelated refactoring or dependency upgrades.

- Use Conventional Commits for commit messages, for example `feat: add clip stretching` or `fix: preserve trimmed source bounds`. Do not commit or push unless requested.

## Project context and reference documents

This is a Rust desktop digital audio workstation (DAW) for macOS, Windows, and Linux, with a headless command-line interface (CLI). Both applications use the same project model and rendering logic. The project format is experimental. There is no fixed track-count limit. Undo/redo and mobile delivery are outside the current MVP.

- Put behavior in the crate that owns it. Do not duplicate rendering or validation in the UI or CLI.
- Follow the accepted [source-container architecture](docs/modular-audio-units.md#one-source-container-per-track): one processing root per track, with reusable source units inside MIDI instruments and independent lanes inside beat instruments. Keep immutable clip content separate from processing state.
- Use focused modules for new cohesive behavior. Keep application composition and public entry points in `lib.rs` or `main.rs`; avoid adding unrelated responsibilities to large files.
- Every modulation provider and destination must use the [shared modulation contract](docs/modulation.md) in `unit-core`. Reuse its source publication, metadata/discovery, scope checks, typed destination entry point, route validation/resolution, and additive offset smoother. Do not implement unit-specific routing loops or source lookup in consumers. Continuous providers must use shared context, dynamic range metadata, and `Continuous` behavior; they cannot own note release. Reuse the contour/continuous resolver composition for amplitude. See [LFO](docs/lfo.md). Keep note scheduling and concrete unit construction in the host; keep audio DSP and final parameter bounds in each portable unit.
- Prefer composition through structs and functions. Use traits when implementations need to vary; avoid a universal panel or engine interface.
- Share dependency versions in the workspace when multiple crates use them. Keep native dependencies behind target-specific configuration. Retain `Cargo.lock` for reproducible application builds.
- Use Rust naming conventions and rustfmt. Add comments for invariants, units, lifetime constraints, and non-obvious decisions. Return useful errors at file, media, and device boundaries; do not use panics for expected failures.

## Audio and editing invariants

- Use the selected project processing rate (44.1/48/88.2/96/176.4/192 kHz; default 48 kHz). Convert imports to that rate and device output separately. Persist the project buffer size (32–4096 samples in powers of two; default 512, including legacy manifests). Rescale frame coordinates with checked arithmetic when changing rate; preserve timing, source offsets, repeat phases, and stretch ratios. Prepare decoded audio, waveforms, and stretch caches on a worker before publishing the full session. Failure retains the original session and playback; success stops output for recreation with the new settings. Keep boundary fades and smoothing at 5 ms for every rate.
- Store timeline positions and durations in integer sample frames. Use explicit names such as `start_frame` and `length_frames`. Treat clip ends as exclusive. Convert to seconds or musical positions at display/input boundaries.
- The ruler currently uses 4/4, with bars and beats counted from 1. Tempo must be positive and finite. Change tempo through `Edit::SetTempo`: move each clip start to retain its beat position, rounded to the nearest sample frame, while preserving audio clip length and source/stretch metadata. MIDI clip lengths, offsets, repeat bases/phases, and pattern frame bounds scale with tempo; note ticks stay unchanged. Reject overlaps or timeline overflow as one transaction. Scale both loop-selection endpoints to retain their beat positions, including when Loop is disabled; round up as with ruler snapping. Keep the playhead frame unchanged.
- Preserve stable project, asset, track, and clip IDs. Reordering preserves identity; copies receive new clip IDs and share their source audio.
- Keep clip lengths positive, frame arithmetic within bounds, and clips on the same track non-overlapping. Validate final group edits as one transaction through `Project::edit` and `Edit::Batch` where applicable.
- Ordinary waveform-edge trims apply to every selected clip using one snapped frame delta. Reject the full shortening edit if any clip would become empty. Clamp audio expansion per clip at source and timeline limits; MIDI source expansion follows the parity contract below. The dragged clip's limit must not cap other clips. Preserve selection and validate final group overlaps atomically. Header looping also applies to the selected group; modifier stretching also applies to the selected group using a shared duration ratio, with each opposite edge fixed. Clamp that ratio at every clip's timeline and 1/8–8 source-ratio bounds. Resolve stretch overlaps with the same directional priority as other resizes: trim covered neighbor edges and remove fully covered clips, including selected clips. Use `Edit::StretchClips`/`Project::stretched_clips` for the complete result. Stage only on mouse release and publish all stretch, trim, and removal changes together after worker preparation succeeds. Failure or cancellation retains the original project and prepared audio.
- Start a waveform drag on the dividing line between two contiguous clips to move their shared boundary: trim one and extend the other, keeping the pair's outer endpoints fixed. Clamp movement to both clips' available source audio and remove either clip when fully covered. Starting more than 3 logical points inside either clip keeps ordinary trimming. The gesture is chosen at the initial press and does not change when the cursor crosses the line. Snap to the grid and source boundaries; Shift bypasses snapping. Preview both clips and commit only on release; Escape or focus loss cancels. If both are selected, treat them as one boundary pair. Other selected clips use the same requested delta with ordinary trim limits; reject the full edit if any of those clips would become empty. Header looping and modifier stretching retain their existing behavior. Use the shared `Project::trimmed_boundary`/`Edit::TrimBoundary` transaction. Capture the dividing-line gesture at the press position within 3 logical points of the dividing line, separate from the wider ordinary trim hit areas.
- Header-edge looping uses one snapped frame delta for the selected group. Preserve each clip's own repeat base and phase. Clamp the common delta at every clip's minimum length and timeline bounds. Resolve resize overlaps by trimming selected or unselected neighbors; remove fully covered clips. Right-edge resizes give earlier clips priority; left-edge resizes give later clips priority. Use the shared `Edit::ResizeClips`/`Project::resized_clips` calculation for previews and release. Commit all range changes and deletions only on mouse release; Escape or focus loss cancels them. Keep Shift bypass, previews, cancellation, and clean no-op releases consistent with group trimming.
- Moves, drag duplication, paste, and file drops take priority over existing destination clips. Use `Project::placed_clips` and `Edit::OverwriteClips` to trim covered edges, remove fully covered clips, or retain both sides when a placement lands in the middle. Preserve source offsets, repeat phases, stretch ratios, names, and colors on the retained pieces. Keep the original ID on the left piece (or the sole surviving piece); assign new IDs to additional right pieces. Remove all moving originals before resolving the full group. Copies receive new IDs and keep their originals as destination neighbors, so a copy can trim, split, or remove its original. Preserve group timing and track gaps, and reject invalid incoming ranges atomically. Preview incoming clips and every affected neighbor without changing project data or playback. Commit moves and drag duplication only on mouse release, paste as one transaction, and file drops only after preparation succeeds. Cancelled gestures and failed imports retain the original arrangement. Keep grid snapping, Shift bypass, timeline clamps, and new-track previews.
- Edits must not change source recordings. Preserve source offsets, repeat bases/phases, stretch ratios, and color overrides across compatible operations.
- Keep original decoded audio separate from prepared stretch audio. Stretch ratios are reduced integer ratios; stretched clip offsets and repeat ranges use stretched-frame coordinates. Use `source_length`, `source_frame`, and the existing cache lookup helpers instead of duplicating this mapping.
- Use the saved stretch engine/revision. Rubber Band R3/Finer is the default, in offline mode with linked stereo channels; Integrated is experimental. Prepare buffers on a worker before applying a stretch edit. Playback, waveforms, and export must resolve the same prepared buffer. Preserve the original clip on processing failure.
- Share mixing behavior between live playback and offline export. Preserve solo precedence, pan/balance behavior, clip/loop boundary fades, and clipping diagnostics.

- Keep effect unit selection in UI state, independent of track/clip/catalog selection. Plain clicks select one unit; Shift-click toggles membership; an empty effects-lane click clears unit selection. With lane focus, Delete/Backspace removes all selected installed units through one `Edit::SetEffects`; preserve surviving IDs/settings and track/clip state. Keep pane focus after removal, consume held-key repeats, and guard text editing, other panes, drags, disabled UI, and jobs/dialogs. Reuse `panels::selection_border` for selected track rows and effect units. Effect header dragging moves selected instances as a group in their existing chain order with a preview and edge scrolling; commit its ordered chain through `Edit::SetEffects` on release only. Cancel on Escape, focus loss, outside drops, or invalidated editing/chain state. Preserve saved settings and compatible DSP history; power/knob gestures and double-click collapse keep their behavior. Do not mark selection, cancellation, or same-position drops as project edits.

- Oscillator pitch modulation must use the [shared source/destination contract](docs/modulation.md) and [pitch behavior](docs/oscillator-modulation.md). Give each oscillator a stable UUID. Use shared targeted routes and controls with `Osc N · Pitch` labels; never route by list index. Pitch accepts per-note and shared sources, including Main. Store amounts in semitones and preserve base transpose and phase during compatible updates. Remove only the removed oscillator's routes. Keep route validation, preparation, smoothing, history retargeting, telemetry, and legacy migration shared and allocation-free on the callback.

## Real-time and background work

The audio callback must remain nonblocking and must not allocate or perform file I/O.

- Do not decode audio, build peaks, stretch clips, serialize manifests, show dialogs, log, acquire locks, or wait on channels in the callback.
- Prepare renderers, buffers, meter handles, and queue capacity on a control or worker thread. Retire old renderers and final audio owners outside the callback.
- Use the existing bounded `rtrb` queues and atomic status values. Handle queue-full and device-failure paths without blocking the callback.
- Run import, source preparation, project I/O, stretching, and export through the existing worker/job paths. Keep expensive work out of egui painting and input handlers.
- Stage changes and publish them after successful work. Retain current project state on failure or cancellation. Route errors and warnings through the existing UI/CLI reporting paths.

Keep linked L/R, independent M/S plus linked final protection, fixed bypass latency, and shared engine alignment/preroll. Follow [Limiter](docs/limiter.md) for ranges, reconstruction limits, state migration, transport, and allocation-free processing.

## Persistence and export

- Projects are folders with `project.json` and an `assets` directory. Source WAV files remain external references; saving a project does not bundle those recordings.
- Preserve source identity and correct relative/absolute path resolution during Save As. New-project Save and Save As use the shared name-then-parent-folder flow. Do not replace an existing project folder through that flow.
- Keep saves and exports transactional. Write temporary outputs and publish only after success. Protect source files and manifests from export replacement, and retain explicit overwrite confirmation.
- Preserve older manifests through appropriate serde defaults when adding optional fields. Add round-trip and invalid-input checks for model changes. Never silently reinterpret existing frame units or source references.
- Missing sources retain clips, warnings, and silent rendering. Shortened sources render unavailable ranges as silence. Unsupported or damaged audio must produce a clear diagnostic.
- Keep desktop and CLI export on the same backend. WAV supports PCM16, PCM24, and float32 at the project rate; MP3 uses the bundled LAME encoder, converting project rates above 48 kHz to 48 kHz. Show the actual export rate in both export dialogs. Preserve deterministic output, format/codec validation, and progress reaching 100% only after file publication.
- WAV imports support mono/stereo PCM16, PCM24, and float32. Export is stereo, defaults to PCM24 for WAV or 192 kbps for MP3, and offers MP3 constant bitrates of 128/192/256/320 kbps. Integer WAV uses deterministic triangular dither; float32 preserves headroom without dither. Device output, integer WAV, and MP3 clamp clipping; float32 reports levels above 0 dBFS. Remember accepted export options for the app session. After destination/replacement confirmation, show progress, finalization, destination, format, warnings, completion, and errors in the shared status dialog; keep long reports scrollable and editing blocked until it closes.
- CLI exit codes are 0 for success, 1 for project/media/processing failures, and 2 for invalid arguments. Missing-source warnings do not fail export.

## Build and validation workflow

Follow the platform prerequisites, build steps, troubleshooting, and packaging instructions in [README.md](README.md#build-and-run). Run the commands below from the repository root with the pinned toolchain.

### Run and headless commands

```sh
cargo run -p daw-desktop
cargo run -p daw-desktop -- examples/demo
cargo build -p daw-cli
cargo run -p daw-cli -- validate --project examples/demo
cargo run -p daw-cli -- render --project examples/demo --output work/mix.wav
cargo run -p daw-cli -- render --project examples/demo --output work/mix.wav --overwrite
cargo run -p daw-cli -- render --project examples/demo --output work/mix.wav --codec float32
cargo run -p daw-cli -- render --project examples/demo --output work/mix.mp3 --format mp3 --bitrate 320
```

Create `work/` before using it as an output directory. If `work/cargo-home` contains the local dependency cache, prefix Cargo commands with `CARGO_HOME="$PWD/work/cargo-home"`. Add `--offline` only when the required dependencies are cached. Do not require this local cache on other machines.

The CLI infers WAV or MP3 from the output extension unless `--format wav|mp3` is supplied. WAV accepts `--codec pcm16|pcm24|float32`; MP3 accepts `--bitrate 128|192|256|320`. Reject incompatible options and mismatched format extensions. The CLI must run without graphics or an audio device.

### Validation

For code changes, run affected checks while developing, then run the workspace checks before completion:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

- Add meaningful tests for changed behavior and failure paths. Keep unit tests near the implementation; use `crates/project/tests/workflow.rs` for storage/render/export workflows and existing egui input tests for interactions. Avoid tests that only repeat implementation details.
- For CLI or shared import/render/export changes, build `daw-cli`, then run `python3 tools/check_cli.py`. It needs the tracked demo and uses temporary output folders.
- `python3 tools/create_demo.py` regenerates tracked demo files. Do not run it over user edits or include regenerated fixtures unless required by the task.
- On macOS, rebuild desktop deliverables with `sh tools/package_macos.sh debug` or `release` when desktop/runtime changes need an updated app. The unsigned bundle is under `target/<profile>/DAW.app`.
- CI calls `.github/workflows/platform.yml` independently for Windows, macOS, and Linux, with fail-fast disabled. Each invocation has separate `test` and `build` jobs; build depends only on that invocation's tests and includes release builds, packaging, and artifact uploads. Do not gate all builds on the aggregate test matrix. Both jobs use `.github/actions/setup-build` for native dependencies, the pinned Rust toolchain, Python, and Cargo caching. Tests run locked workspace checks and CLI smoke checks. Keep the portable Windows executable with its project license and dependency notices, and retain the same notices in macOS DMG and Linux ZIP artifacts. Use the native scripts in `tools` rather than duplicating packaging commands in the workflow.
- Keep CI command output visible in the console and in log artifacts. Preserve command failures when using `tee`, upload logs on failure, and write job summaries through `tools/summarize_ci.py`. Windows setup selects the MSVC linker by absolute path to avoid Git Bash's `link.exe`. UI background-job tests use a bounded 30-second wall-clock deadline for slower hosted workers.
- For documentation-only changes, check content, links, commands against their definitions, and `git diff --check`; do not rebuild or run unrelated audio tests.
- Use temporary folders for tests. Do not overwrite user projects, recordings, or exports. Review `git diff` and `git status` before completion.
- Once relevant checks pass, repeat them only after new changes or unresolved failures. Record unavailable device/platform checks explicitly; automated egui tests do not establish native gesture behavior.
