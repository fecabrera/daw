# MIDI patterns and oscillators

The first implementation adds MIDI tracks, immutable pattern sources, a basic piano roll in Editor, and an oscillator instrument in Units. Audio tracks retain their existing source behavior. Beat tracks, effect chains, and instrument graph editing remain pending.

## Controls

1. In Timeline, choose Track > Add MIDI track. MIDI track and pattern creation is available only in Timeline, including MIDI paste and track duplication.
2. Double-click empty space on a MIDI timeline lane to create a one-beat pattern at the snapped position. Creation selects the clip and stays in Timeline. Shift bypasses snapping. Existing saved pattern lengths remain unchanged.
3. Double-click a MIDI clip or choose Editor clip from its context menu to open its pattern. Editor shows the selected track: a clip strip below the ruler and all its MIDI patterns in one piano roll. Each pattern has a visible border, including contiguous patterns. Select a clip in the strip or edit its notes to make it primary without moving the viewport. Use the playback toolbar’s track dropdown to switch the editor to another track. It selects that track’s earliest clip, or shows its empty editor when it has no clips. With no track, Editor prompts for a selection; audio clips show that their editor is pending.
4. Click and drag empty piano-roll space to select all notes that intersect the selection box. Selection can span patterns and gaps on the selected track. Shift-click toggles a note without clearing other selected notes, including notes in other patterns. Shift-drag in empty space toggles the notes inside the box against the selection at the initial press; notes outside it retain their selection. Repeated occurrences of one source note toggle once per clip. The box captures its Shift state at the initial press. A Shift-click on empty space keeps the selection; a plain empty-space click clears it. Hold Command on macOS or Ctrl on Windows/Linux while clicking empty space to add a grid-sized note, or while dragging to draw from the start point to the end point. The modifier at the initial press selects the gesture mode; changing it during the drag does not switch modes. The starting row fixes its pitch. Drawing backwards uses the ordered time range. Preview the new note and same-pitch neighbor trims, splits, and removals; commit them together on release. Different pitches retain their notes and can sound together. Drag a note body to change its start and pitch. If the note is selected, move the whole selected group with one time and pitch displacement, including notes in different patterns. Hold Option on macOS or Ctrl on Windows/Linux during the move to duplicate those notes. Copies have new IDs and retain note duration and velocity; originals stay intact. The copy modifier can change during a move, and its state at release decides whether to move or copy. Select the moved notes or copies after release. Clamp the group together at source bounds and the MIDI pitch range to retain its spacing, allowing one-tick rounding between differently stretched patterns. Shift bypasses time snapping. A drag with no effective displacement creates no copies and does not mark a change. Drag either edge of a selected note to resize the whole selected group by one shared project-time change, keeping each note’s opposite edge fixed. Clamp the group when any note reaches a pattern boundary or its one-tick minimum length. Differently stretched patterns round the change to source ticks. Dragging an unselected note edge resizes only that note. Holding the copy modifier on an edge still resizes without duplication. Notes preview until release; changes across patterns commit in one batch. Escape or focus loss cancels a drag and restores the previous note selection. Double-click without Shift or secondary-click deletes a note. Repeated Shift-clicks toggle selection without deleting notes. Delete/Backspace removes all selected notes in one transaction; the pattern context menu’s Delete note removes its selected note. These keys do not delete the containing clip in Editor.
5. Subdivisions and note snapping follow horizontal zoom automatically, using the same visible-step calculation as Timeline. Shift bypasses time snapping. Notes clamp to the pattern and MIDI pitch range. Velocity is 1–127, with a default of 100. Select a note and secondary-click the pattern header to adjust velocity or use Delete note; these controls do not add a permanent row above the piano roll. Editor uses the same project ruler, playhead, loop selection, snapping, and toolbar zoom control as Timeline. Its horizontal zoom and scroll stay independent; the zoom control has the same design and position in the playback toolbar. The ruler, track strip, pattern borders, notes, and playhead share project time and the same horizontal transform. Display trimmed ranges, stretch timing, and visible repetitions at their arrangement positions; editing a repetition updates that clip’s source. Piano keys stay pinned while notes scroll. Below half a pixel per repetition, show pitch coverage; zoom in to edit individual notes at that density. Empty gaps do not create patterns. Seeking and left-edge expansion clamp at project zero.
6. Drag either edge of a pattern in the track strip to resize its source and visible clip range. The right edge changes its end. The left edge moves the clip start, crops or pads the source, and adjusts note ticks so retained notes keep their project timing within sample-frame rounding. Extending left adds space before existing notes. Left resizing keeps the clip end fixed. Remove notes wholly outside the new bounds and shorten crossing notes. Preview until release; Escape or focus loss cancels. The minimum source length is one tick. Shift bypasses snapping.
7. In Units, select the track from the playback toolbar and configure its Oscillator panel. Its full-width header uses the active accent, centered text with the mixer strip’s contrast rule, and the mixer strip’s compact height and font size. One thin divider separates the playback toolbar from Units, without an extra gap. Choose Sine (default), Saw, Square, or Triangle. The panel has no oscillator checkbox, voice-mode label, or pattern-edit button. Transpose matches the waveform field width; the gain field fills the remaining row after its knob. Both numeric fields center their text. Transpose is −48 to +48 semitones, default 0. Source gain is −60 to +12 dB, default −12 dB, before track gain/pan. The shared gain knob supports Shift for fine adjustment.

Patterns use the existing clip move, copy/paste, drag duplication, trim, loop, stretch, and overlap rules. Audio sources belong on audio tracks; MIDI sources belong on MIDI tracks. Wrong-type placements fail atomically. Moving a MIDI clip into new timeline space creates a MIDI track with its source track's instrument settings.

## Model and ownership

- `TrackKind` defaults to Audio for older manifests. MIDI tracks own versioned oscillator settings; audio tracks reject source instruments in core validation.
- MIDI patterns are embedded assets with stable source IDs. Notes have stable IDs, pitch, velocity, start ticks, and duration ticks. One beat is 960 ticks. New patterns default to 960 ticks (one beat).
- Clip frame ranges, source offsets, repeat bases/phases, and stretch ratios stay separate from pattern content. Pattern edits create a new asset and update only the edited clip's source reference. Other clips and clipboard copies retain the original asset. No-op edits retain the source ID.
- Source resizing creates a new asset for the edited clip and commits note, range, and neighbor changes together. Full-source clips follow the new source length. Trimmed clip ranges, repeat bases, and looped arrangement lengths follow the same duration change within source bounds. Clamp offsets and repeat phases to the new source bounds and preserve stretch. Resizing a looped source changes its repeat spacing; source edits remain shared across that clip’s visible repetitions. Expansion uses the existing trim/split/removal rules, giving the edited clip priority. Other source users retain the previous pattern.
- Saving includes pattern data and instrument settings in `project.json`. MIDI assets have no file path and are excluded from external-file resolution and overwrite checks. Source recordings remain external references.
- Tempo changes scale MIDI clip starts, durations, offsets, repeats, and derived source-frame bounds. Note ticks stay fixed. Audio clip durations stay fixed. The whole tempo change rejects overlaps, invalid ranges, or overflow atomically.
- Processing-rate changes retain note ticks and musical timing, rescale clip ranges, and rebuild the prepared voices through the existing session replacement path.

## Shared units and rendering

`daw-unit-core` defines backend-independent descriptors, typed ports, versioned oscillator settings, processing context, and the prepared mono source lifecycle. `daw-oscillator` implements that lifecycle with FunDSP. Neither crate depends on the DAW model, UI, or devices. Standalone tools can reuse this source contract; no standalone app is included yet.

The engine prepares note schedules, oscillator state, and voice slots before publication. Events use project sample frames. At a shared frame, note-offs precede note-ons; simultaneous note-ons sort by stable note ID. Each simultaneous note has its own oscillator voice and fixed 5 ms amplitude ramps. Prepare enough slots for the pattern's overlapping notes and release tails; reuse slots once those tails end. There is no fixed voice cap or runtime voice stealing. Note-offs affect only their assigned note. Slots never allocate during audio processing.

Seek resets voices and reconstructs all notes still held at the new source position. Stop resets voices; pause preserves voice state. Clip/repeat/transport-loop boundaries end the previous note. Mute/solo suppress output while voices keep advancing. Gain/pan-only renderer replacements transfer compatible voice state without callback allocation; instrument/pattern changes publish new prepared state with the existing output transition.

Playback and WAV/MP3 export share sequential oscillator processing, note timing, clip fades, and mixer behavior. Export renders the arrangement once without transport looping or playback start/pause ramps. `RenderPlan::sample_at` and `render` remain prepared-audio lookup APIs; use `Renderer::render_offline` for mixed audio/MIDI rendering.

## Current limits and follow-up work

- Pattern length starts at one beat and can be resized through its header edges. Timeline looping repeats the source without changing its content.
- One oscillator instrument per MIDI track, with multiple voices for polyphonic patterns. Oscillator frequencies at or above the processing Nyquist limit render silence. No MIDI file import/export, hardware MIDI, live note input, audition keyboard, or note clipboard yet.
- No audio/beat editor, effect chain, graph connections, saved graph layouts, missing-unit fallback, or standalone interface yet. The larger [Units design](modular-audio-units.md) remains the source for that scope.
- Native device stability and the full eight-voice workload with representative effects require separate validation. Automated rendering and input tests do not establish device or cross-platform behavior.
