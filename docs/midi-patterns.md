# MIDI patterns and oscillators

The first implementation adds MIDI tracks, immutable pattern sources, a basic piano roll in Editor, and an oscillator instrument in Units. Audio tracks retain their existing source behavior. Beat tracks, effect chains, and instrument graph editing remain pending.

## Controls

1. In Timeline, choose Track > Add MIDI track. MIDI track and pattern creation is available only in Timeline, including MIDI paste and track duplication.
2. Double-click empty space on a MIDI timeline lane to create a one-beat pattern at the snapped position. Creation selects the clip and stays in Timeline. Shift bypasses snapping. Existing saved pattern lengths remain unchanged.
3. Double-click a MIDI clip or choose Editor clip from its context menu to open its pattern. Editor shows the selected track: a clip strip below the ruler and all its MIDI patterns in one piano roll. Each pattern has a visible border, including contiguous patterns. Select a clip in the strip or edit its notes to make it primary without moving the viewport. Use the playback toolbar’s track dropdown to switch the editor to another track. It selects that track’s earliest clip, or shows its empty editor when it has no clips. With no track, Editor prompts for a selection; audio clips show that their editor is pending.
4. Click and drag empty piano-roll space to select all notes that intersect the selection box. Selection can span patterns and gaps on the selected track. Shift-click toggles a note without clearing other selected notes, including notes in other patterns. Shift-drag in empty space toggles the notes inside the box against the selection at the initial press; notes outside it retain their selection. Repeated occurrences of one source note toggle once per clip. The box captures its Shift state at the initial press. A Shift-click on empty space keeps the selection; a plain empty-space click clears it. Hold Command on macOS or Ctrl on Windows/Linux while clicking empty space to add a grid-sized note, or while dragging to draw from the start point to the end point. The modifier at the initial press selects the gesture mode; changing it during the drag does not switch modes. The starting row fixes its pitch. Drawing backwards uses the ordered time range. Preview the new note and same-pitch neighbor trims, splits, and removals; commit them together on release. Different pitches retain their notes and can sound together. Drag a note body to change its start and pitch. If the note is selected, move the whole selected group with one time and pitch displacement, including notes in different patterns. Hold Option on macOS or Ctrl on Windows/Linux during the move to duplicate those notes. Copies have new IDs and retain note duration and velocity; originals stay intact. The copy modifier can change during a move, and its state at release decides whether to move or copy. Select the moved notes or copies after release. Clamp the group together at source bounds and the MIDI pitch range to retain its spacing, allowing one-tick rounding between differently stretched patterns. Shift bypasses time snapping. A drag with no effective displacement creates no copies and does not mark a change. Drag either edge of a selected note to resize the whole selected group by one shared project-time change, keeping each note’s opposite edge fixed. Clamp the group when any note reaches a pattern boundary or its one-tick minimum length. Differently stretched patterns round the change to source ticks. Dragging an unselected note edge resizes only that note. Holding the copy modifier on an edge still resizes without duplication. Notes preview until release; changes across patterns commit in one batch. Escape or focus loss cancels a drag and restores the previous note selection. Double-click without Shift or secondary-click deletes a note. Repeated Shift-clicks toggle selection without deleting notes. Delete/Backspace removes all selected notes in one transaction; the pattern context menu’s Delete note removes its selected note. These keys do not delete the containing clip in Editor.
5. Subdivisions and snapping use the shared Timeline grid in project time. Pattern edges, note drawing, note moves, and note resizes snap to absolute ruler positions within six logical points, with bars before beats before visible subdivisions. Positions outside that radius remain free. Clamp at source/project bounds before snapping. Shift bypasses snapping for each gesture and can change while dragging. Convert the shared result to source ticks for trimmed, repeated, and stretched patterns; retain source limits and one-tick minimums. A click-created note lasts one visible project subdivision, converted to source ticks. Notes clamp to the pattern and MIDI pitch range. Velocity is 1–127, with a default of 100. Select a note and secondary-click the pattern header to adjust velocity or use Delete note; these controls do not add a permanent row above the piano roll. Editor uses the same project ruler, playhead, loop selection, snapping, and toolbar zoom control as Timeline. Its horizontal zoom and scroll stay independent; the zoom control has the same design and position in the playback toolbar. The ruler, track strip, pattern borders, notes, and playhead share project time and the same horizontal transform. Display trimmed ranges, stretch timing, and visible repetitions at their arrangement positions; editing a repetition updates that clip’s source. Piano keys stay pinned while notes scroll. Below half a pixel per repetition, show pitch coverage; zoom in to edit individual notes at that density. Empty gaps do not create patterns. Seeking and left-edge expansion clamp at project zero.
6. Drag either edge of a pattern in the track strip to resize its source and visible clip range. The right edge changes its end. Snap the edge’s project position, rather than rounding the drag distance; off-grid patterns can reach the ruler grid. The left edge moves the clip start, crops or pads the source, and adjusts note ticks so retained notes keep their project timing within sample-frame rounding. Extending left adds space before existing notes. Left resizing keeps the clip end fixed. Remove notes wholly outside the new bounds and shorten crossing notes. Preview until release; Escape or focus loss cancels. The minimum source length is one tick. Shift bypasses snapping.
7. In Units, select the track from the playback toolbar and configure its Oscillator panel. It contains one vertical knob column per oscillator, arranged horizontally. Each strip has an 18-point circular Lucide Power button centered below its knobs. Omit the strip name label; retain the source number in the tooltip and accessibility name. On uses the view controls’ accent-tinted fill with a 1-point border and icon in the current accent color. Off uses the secondary text color, matching the former dim label, for both icon and border. The button controls only that source and provides a tooltip, accessible name, and on/off state. Mute preserves the source gain and settings. One 1-point theme-aware separator blended halfway between the panel and border colors separates every adjacent strip, including the final oscillator and Add, through the full strip body, from just below the unit header to the bottom border. Its contrast is lower than the panel borders. Each oscillator strip uses the shared panel padding equally on all four sides. Each oscillator strip has a fixed 90-point width, including padding, independent of the number of sources. Each strip owns its container and internal padding. All strips have the same height and meet at one separator, without extra gap spacing. The add strip has the same internal padding on all sides and an 18-point circular Plus button centered on both axes. Its visible circle uses the same shared renderer as Power, including border, inactive colors, icon scale, and hover feedback. The painted outer diameter, including the border, is 18 points for both controls. The whole add strip is one button: its background changes on hover/focus, and clicking anywhere in it, including padding, adds one default oscillator on release. Right-click a column or knob and choose Remove oscillator to remove that source. Removing the last source leaves the instrument silent, with the add button available. Scroll horizontally when columns exceed the available width. Its full-width header uses the active accent, centered text with the mixer strip’s contrast rule, and the mixer strip’s compact height and font size. One thin divider separates the playback toolbar from Units, without an extra gap. Stack the three controls in this order: Waveform, Pitch, Gain. Each compact row contains an aligned standard knob without a parameter-name label. Retain parameter names and current values in tooltips and accessibility information. Do not show a separate waveform name or pitch/gain value boxes. Waveform shows small Sine (default), Saw, Square, and Triangle diagrams around the knob, and highlights the active shape. It wraps continuously in both directions during dragging and arrow-key input. Its row reserves space for the diagrams while retaining knob alignment with the other rows. Pitch steps by whole semitones and shows reference marks every 12 semitones, with a longer, brighter zero mark and a small current pitch value above it. Label the pitch endpoints “−48” and “+48” below their marks. Gain knobs support optional dB reference ticks; enable them in Oscillator from −∞ through +12 dB, with a stronger unity mark, the current gain in dB above it (−∞ for silence), and −∞/+12 endpoint labels. The panel has no oscillator checkbox, voice-mode label, or pattern-edit button. Use the knobs to adjust parameters; their tooltips show current values. All knob types use the shared base widget, including drag accumulation, bounds or cyclic wrapping, choice diagrams, arrow-key steps, Shift for fine adjustment, and double-click reset. Pitch is −48 to +48 semitones, default 0. Source gain is exact silence (−∞) to +12 dB, default −12 dB, before track gain/pan. The shared gain knob supports Shift for fine adjustment.

Patterns use the existing clip move, copy/paste, drag duplication, trim, loop, stretch, and overlap rules. Audio sources belong on audio tracks; MIDI sources belong on MIDI tracks. Wrong-type placements fail atomically. Moving a MIDI clip into new timeline space creates a MIDI track with its source track's instrument settings.

## Model and ownership

- `TrackKind` defaults to Audio for older manifests. MIDI tracks own one versioned oscillator instrument with a list of independently configured oscillators; audio tracks reject source instruments in core validation.
- MIDI patterns are embedded assets with stable source IDs. Notes have stable IDs, pitch, velocity, start ticks, and duration ticks. One beat is 960 ticks. New patterns default to 960 ticks (one beat).
- Clip frame ranges, source offsets, repeat bases/phases, and stretch ratios stay separate from pattern content. Pattern edits create a new asset and update only the edited clip's source reference. Other clips and clipboard copies retain the original asset. No-op edits retain the source ID.
- Source resizing creates a new asset for the edited clip and commits note, range, and neighbor changes together. Full-source clips follow the new source length. Trimmed clip ranges, repeat bases, and looped arrangement lengths follow the same duration change within source bounds. Clamp offsets and repeat phases to the new source bounds and preserve stretch. Resizing a looped source changes its repeat spacing; source edits remain shared across that clip’s visible repetitions. Expansion uses the existing trim/split/removal rules, giving the edited clip priority. Other source users retain the previous pattern.
- Saving includes pattern data and instrument settings in `project.json`. MIDI assets have no file path and are excluded from external-file resolution and overwrite checks. Source recordings remain external references.
- Tempo changes scale MIDI clip starts, durations, offsets, repeats, and derived source-frame bounds. Note ticks stay fixed. Audio clip durations stay fixed. The whole tempo change rejects overlaps, invalid ranges, or overflow atomically.
- Processing-rate changes retain note ticks and musical timing, rescale clip ranges, and rebuild the prepared voices through the existing session replacement path.

## Shared units and rendering

`daw-unit-core` defines backend-independent descriptors, typed ports, versioned oscillator and instrument settings, processing context, and the prepared mono source lifecycle. Saved instruments contain an oscillator list; older single-oscillator settings load as a one-item list. Empty lists are valid and render silence. Each oscillator saves its mute state; missing mute fields default to false, including legacy single-oscillator settings. Validate every source before committing a change. `daw-oscillator` implements that lifecycle with FunDSP. Neither crate depends on the DAW model, UI, or devices. Standalone tools can reuse this source contract; no standalone app is included yet.

The engine prepares note schedules, oscillator state, and voice slots before publication. Events use project sample frames. At a shared frame, note-offs precede note-ons; simultaneous note-ons sort by stable note ID. Each simultaneous note has independent state for every oscillator in the instrument and fixed 5 ms amplitude ramps. Each source applies its own waveform, pitch, and gain. Muted sources continue advancing with zero output. Sum the sources without automatic normalization, then apply the shared note envelope and velocity before track processing. Prepare enough slots for the pattern's overlapping notes and release tails; reuse slots once those tails end. There is no fixed voice cap or runtime voice stealing. Note-offs affect only their assigned note. Slots never allocate during audio processing.

Seek resets voices and reconstructs all notes still held at the new source position. Stop resets voices; pause preserves voice state. Clip/repeat/transport-loop boundaries end the previous note. Mute/solo suppress output while voices keep advancing. Mixer gain/pan and oscillator gain/pitch/mute changes transfer compatible voice state without callback allocation. Oscillator gain and mute changes use 5 ms amplitude ramps; pitch changes use 5 ms frequency ramps. These changes preserve phase, held notes, and envelope progress, including when a new change arrives during a ramp. These changes retain any existing transport transition instead of restarting it. Waveform, source-count, and pattern changes publish new prepared state with the existing output transition. The control is named Pitch; the saved `transpose` field remains unchanged for project compatibility.

Playback and WAV/MP3 export share sequential oscillator processing, note timing, clip fades, and mixer behavior. Export renders the arrangement once without transport looping or playback start/pause ramps. `RenderPlan::sample_at` and `render` remain prepared-audio lookup APIs; use `Renderer::render_offline` for mixed audio/MIDI rendering.

## Current limits and follow-up work

The accepted [source-container architecture](modular-audio-units.md#one-source-container-per-track) gives each MIDI track one instrument containing reusable oscillator units, modulators, and internal processing. The instrument owns routing and note/voice allocation and exposes one output bus to track effects and gain/pan. The current Oscillator module implements multiple oscillator sources with a summed output. Modulators, internal effects, and user-defined routing remain planned.

- Pattern length starts at one beat and can be resized through its header edges. Timeline looping repeats the source without changing its content.
- One oscillator instrument per MIDI track, containing zero or more oscillator sources and multiple voices for polyphonic patterns. Oscillator frequencies at or above the processing Nyquist limit render silence. No MIDI file import/export, hardware MIDI, live note input, audition keyboard, or note clipboard yet.
- No audio/beat editor, effect chain, graph connections, saved graph layouts, missing-unit fallback, or standalone interface yet. The larger [Units design](modular-audio-units.md) remains the source for that scope.
- Native device stability and the full eight-voice workload with representative effects require separate validation. Automated rendering and input tests do not establish device or cross-platform behavior.
