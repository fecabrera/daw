# Audio and editing invariants

- Use the selected project processing rate (44.1/48/88.2/96/176.4/192 kHz; default 48 kHz). Convert imports to that rate and device output separately. Persist the project buffer size (32–4096 samples in powers of two; default 512, including legacy manifests). Rescale frame coordinates with checked arithmetic when changing rate; preserve timing, source offsets, repeat phases, and stretch ratios. Prepare decoded audio, waveforms, and stretch caches on a worker before publishing the full session. Failure retains the original session and playback; success stops output for recreation with the new settings. Keep boundary fades and smoothing at 5 ms for every rate.
- Store timeline positions and durations in integer sample frames. Use explicit names such as `start_frame` and `length_frames`. Treat clip ends as exclusive. Convert to seconds or musical positions at display/input boundaries.
- Use the saved project time signature (default 4/4), with bars and beats counted from 1. Signature edits change display/grid/click grouping without changing tempo or clip/note/frame timing. Tempo must be positive and finite. Change tempo through `Edit::SetTempo`: move each clip start to retain its beat position, rounded to the nearest sample frame, while preserving audio clip length and source/stretch metadata. MIDI clip lengths, offsets, repeat bases/phases, and pattern frame bounds scale with tempo; note ticks stay unchanged. Reject overlaps or timeline overflow as one transaction. Scale both loop-selection endpoints to retain their beat positions, including when Loop is disabled; round up as with ruler snapping. Keep the playhead frame unchanged.
- Preserve stable project, asset, track, and clip IDs. Reordering preserves identity; copies receive new clip IDs and share their source audio.
- Keep clip lengths positive, frame arithmetic within bounds, and clips on the same track non-overlapping. Validate final group edits as one transaction through `Project::edit` and `Edit::Batch` where applicable.
- Ordinary waveform-edge trims apply to every selected clip using one snapped frame delta. Reject the full shortening edit if any clip would become empty. Clamp audio expansion per clip at source and timeline limits; MIDI source expansion follows the parity contract below. The dragged clip's limit must not cap other clips. Preserve selection and validate final group overlaps atomically. Header looping also applies to the selected group; modifier stretching also applies to the selected group using a shared duration ratio, with each opposite edge fixed. Clamp that ratio at every clip's timeline and 1/8–8 source-ratio bounds. Resolve stretch overlaps with the same directional priority as other resizes: trim covered neighbor edges and remove fully covered clips, including selected clips. Use `Edit::StretchClips`/`Project::stretched_clips` for the complete result. Stage only on mouse release and publish all stretch, trim, and removal changes together after worker preparation succeeds. Failure or cancellation retains the original project and prepared audio.
- Start a waveform drag on the dividing line between two contiguous clips to move their shared boundary: trim one and extend the other, keeping the pair's outer endpoints fixed. Clamp movement to both clips' available source audio and remove either clip when fully covered. Starting more than 3 logical points inside either clip keeps ordinary trimming. The gesture is chosen at the initial press and does not change when the cursor crosses the line. Snap to the grid and source boundaries; Shift bypasses snapping. Preview both clips and commit only on release; Escape or focus loss cancels. If both are selected, treat them as one boundary pair. Other selected clips use the same requested delta with ordinary trim limits; reject the full edit if any of those clips would become empty. Header looping and modifier stretching retain their existing behavior. Use the shared `Project::trimmed_boundary`/`Edit::TrimBoundary` transaction. Capture the dividing-line gesture at the press position within 3 logical points of the dividing line, separate from the wider ordinary trim hit areas.
- Header-edge looping uses one snapped frame delta for the selected group. Preserve each clip's own repeat base and phase. Clamp the common delta at every clip's minimum length and timeline bounds. Resolve resize overlaps by trimming selected or unselected neighbors; remove fully covered clips. Right-edge resizes give earlier clips priority; left-edge resizes give later clips priority. Use the shared `Edit::ResizeClips`/`Project::resized_clips` calculation for previews and release. Commit all range changes and deletions only on mouse release; Escape or focus loss cancels them. Keep Shift bypass, previews, cancellation, and clean no-op releases consistent with group trimming.
- Moves, drag duplication, paste, and file drops take priority over existing destination clips. Use `Project::placed_clips` and `Edit::OverwriteClips` to trim covered edges, remove fully covered clips, or retain both sides when a placement lands in the middle. Preserve source offsets, repeat phases, stretch ratios, names, and colors on the retained pieces. Keep the original ID on the left piece (or the sole surviving piece); assign new IDs to additional right pieces. Remove all moving originals before resolving the full group. Copies receive new IDs and keep their originals as destination neighbors, so a copy can trim, split, or remove its original. Preserve group timing and track gaps, and reject invalid incoming ranges atomically. Preview incoming clips and every affected neighbor without changing project data or playback. Commit moves and drag duplication only on mouse release, paste as one transaction, and file drops only after preparation succeeds. Cancelled gestures and failed imports retain the original arrangement. Keep grid snapping, Shift bypass, timeline clamps, and new-track previews.
- Edits must not change source recordings. Preserve source offsets, repeat bases/phases, stretch ratios, and color overrides across compatible operations.
- Select a time range with Command-drag on macOS or Ctrl-drag on Windows/Linux in the Timeline arrangement. The range may cover partial clips, several clips, and silence. Drag it to move, hold Option on macOS or Ctrl on Windows/Linux to duplicate, copy with the clip shortcut, and delete to remove only that time. Reuse `Clip::retained_range` through `Project::clip_range_slices` and `Project::without_clip_range`, then place moved or copied pieces with `Project::placed_clips`. On Windows/Linux, Ctrl-drag inside the range duplicates it and Ctrl-drag elsewhere selects a new range. Snap with the project grid and keep Shift bypass. A click outside the range, Escape, or a whole-clip selection clears it. Failure leaves the project unchanged.
- Split selected clips at the playhead through `Project::split_clips`, the Clip menu, Command+T on macOS or Ctrl+T on Windows/Linux, and the shared clip context menu. Enable it in Timeline when the playhead is strictly inside at least one selected clip. Split every selected clip that contains that frame in one transaction, and leave the other selected clips unchanged. The original clip keeps its ID and ends at the playhead; the new clip starts there. Audio keeps its source recording, offset, loop phase, stretch, name, and color through `Edit::Split`. MIDI notes that cross the playhead follow the application setting `MidiNoteSplit`: Split into two is the default and divides the note, while Preserve first keeps the first part on the original clip. Non-looping MIDI keeps stretch and writes separate patterns only when a note crosses, leaving other users of the original pattern unchanged. A looping MIDI clip whose note crosses the playhead becomes two unlooped patterns containing the notes heard on each side. Failure leaves the project unchanged.
- Keep original decoded audio separate from prepared stretch audio. Stretch ratios are reduced integer ratios; stretched clip offsets and repeat ranges use stretched-frame coordinates. Use `source_length`, `source_frame`, and the existing cache lookup helpers instead of duplicating this mapping.
- Use the saved stretch engine/revision. Rubber Band R3/Finer is the default, in offline mode with linked stereo channels; Integrated is experimental. Prepare buffers on a worker before applying a stretch edit. Playback, waveforms, and export must resolve the same prepared buffer. Preserve the original clip on processing failure.
- Share mixing behavior between live playback and offline export. Preserve solo precedence, pan/balance behavior, clip/loop boundary fades, and clipping diagnostics.

- Keep effect unit selection in UI state, independent of track/clip/catalog selection. Plain clicks select one unit; Shift-click toggles membership; an empty effects-lane click clears unit selection. With lane focus, Delete/Backspace removes all selected installed units through one `Edit::SetEffects`; preserve surviving IDs/settings and track/clip state. Keep pane focus after removal, consume held-key repeats, and guard text editing, other panes, drags, disabled UI, and jobs/dialogs. Use shared selection background fills without outlines for selected tracks, beat subtracks and instrument-layer headers. Reuse `panels::selection_border` for selected effect units. Effect header dragging moves selected instances as a group in their existing chain order with a preview and edge scrolling; commit its ordered chain through `Edit::SetEffects` on release only. Cancel on Escape, focus loss, outside drops, or invalidated editing/chain state. Preserve saved settings and compatible DSP history; power/knob gestures and double-click collapse keep their behavior. Do not mark selection, cancellation, or same-position drops as project edits.

- Oscillator pitch modulation must use the [shared source/destination contract](../../../specs/modulation/contract.md) and [pitch behavior](../../../specs/modulation/oscillator-pitch.md). Give each oscillator a stable UUID. Use shared targeted routes and controls with `Osc N · Pitch` labels; never route by list index. Pitch accepts per-note and shared sources, including Main. Store amounts in semitones and preserve base transpose and phase during compatible updates. Remove only the removed oscillator's routes. Keep route validation, preparation, smoothing, history retargeting, telemetry, and legacy migration shared and allocation-free on the callback.

- Sampler follows [Sampler source](../../../specs/instruments/sampler.md). A regular layer can have Oscillator, Sampler/Granulizer or Noise; multiple oscillator strips remain allowed within Oscillator. Catalog source additions replace the existing source; adding Oscillator to an existing Oscillator appends a strip. External audio-file drops on a regular MIDI or beat-subtrack layer install Sampler atomically after preparation. Preserve one-source exclusivity in core transactions, including installed moves/copies. Keep sources pinned first and out of Main. Reuse shared unit shells, component editing, clip mapping, waveform/clip-header painting, range selection, and Gain. Sampler duration mode uses a standard Off/Time (ms)/Bars dropdown in the duration input group; keep it available in Off with a disabled original-duration millisecond readout. Use a One-shot/Gate dropdown beside root note and duration; reuse the duration selector helper. Keep Gain as the only strip knob and retain the shared strip footer. Put the sample name in its clip header. Reuse the standard musical grid/ruler painters, scaling the local input clock by the selected region output/input ratio in Time/Bars and mapping snapping through the same ratio. Use one standard 90-point control strip with a centered Sample footer and full-height divider. Join root note and sharp within one shared input frame and place that group with duration and Trigger on one horizontal row without visible field labels; retain tooltips/accessibility. Bars uses whole 1-bar steps with a minimum of 1. Root note reuses the standard drag input, shared piano-roll formatter/parser, and a sharp toggle; drag in semitone steps. MIDI notes transpose relative to the root across the full MIDI 0–127 range. Reuse the selected offline stretch/pitch backend, prepare required note pitches on workers, and publish complete playable banks. Validated MIDI edits can enter the editor/history before audio is ready under the [background preparation contract](../../../specs/architecture/background-audio-preparation.md); keep pending status, save revisions and previous playback explicit. Note-on selects a prepared buffer without allocation or final-owner retirement. Decode, compose input ranges, build peaks, and stretch on workers before atomic publication. Sampler Gain is a per-note destination through the shared modulation API; reuse cached providers, typed routes, smoothing, connection strips, Gain amount mapping, and processed extrema snapshots. Keep other Sampler controls discrete/unmodulated. Keep callback playback, seek reconstruction, stereo Amplitude application, and prepared sample-position telemetry shared and allocation-free.
