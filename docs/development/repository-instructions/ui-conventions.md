# UI conventions

- Follow the [canonical tooltip presentation contract](../../../specs/views/tooltips.md) for all app and plugin-editor tooltips and Details reports.

- Every unit with a variable number of strips must allow reordering of all removable strips. Keep fixed strips, including Add and Out, in their assigned positions. Reuse Oscillator's shared drag helpers and the strip gesture lifecycle; preserve strip identities, settings, modulation connections and automation bindings. Follow the [variable-strip reordering contract](../../../specs/architecture/modular-audio-units.md#variable-strip-reordering) for release-only commits, cancellation, persistence and tests. This requirement applies to built-in units and standalone editors; documented implementation gaps are pending work, not exceptions.

- New effect units include built-in DAW integration and standalone CLAP/VST3 and macOS AUv2 products by default, unless the user explicitly narrows the scope. Add the typed plugin contract, shared editor bindings, checked manifest, packaging discovery and CI coverage together.

- Built-in effects and standalone plugin editors must call the same `unit-ui` body renderers. Keep control order, knob specifications, labels, strip geometry, footers and meter placement shared. Keep DAW shells/modulation and SDK automation adapters in their host crates. Compare all effect editors against the built-in bodies when changing shared effect presentation; see [plugin editor parity](../../../specs/architecture/all-effect-plugin-builds.md#built-in-editor-parity).

- Use `unit-ui::menus::Dropdown` for dropdown selectors and its shared popup style/layout for submenus. Follow [canonical dropdowns and catalog spacing](../../../specs/views/dropdowns.md): Small popup text for unit selectors and modulation submenus through `Dropdown::small_items()` / `small_popup_style`, regular popup text elsewhere, rounded full-row highlights, 4-point inner padding, outer margins and item gaps, ChevronRight submenu arrows, and unpadded dividers. Effects, Components and Chords catalogs reuse the same spacing constants through `ControlPanel::catalog_body` and `catalog_row`; retain their Small text and existing interactions.

- Disabled bands use the theme's secondary grey for meter fills, including boost, reduction, overload, and residual readings during band transitions. Reuse `meters::band_color` for this rule across current and future band monitors. Keep the meter's scale, readings, geometry and accessibility unchanged; apply the shared concise tooltip contract.

- All unit level meters use the track level palette: `palette.meter` green at or below 0 dBFS and `palette.error` red above 0 dBFS, independently of the accent color. Apply this to output and band level rails in built-in units and standalone editors through the shared meter painters. Keep disabled bands secondary grey, bypassed rails empty and held-peak markers secondary grey. Gain-reduction and signed gain-change monitors retain their separate colors and scales. See the [standard level-meter contract](../../../specs/architecture/modular-audio-units.md#standard-effect-out-strip-meter).

- Every audio unit with an Out/Output strip must include the shared level meter and held-peak indicator. Reuse the existing rail painter and prepared monitoring path without changing strip geometry. Source units use the [source output contract](../../../specs/architecture/modular-audio-units.md#source-unit-out-strip-meters): sum voices after source output controls and note velocity, before Amplitude and downstream buses. Meter clicks must not start unit drags or edit the project. Do not add output strips to units that have none.

- Register instrument catalog components once in `instrument_catalog.rs::ENTRIES`, using `Entry::layer` with its category and an optional `.with_main` installation function, or `Entry::provider` with its typed modulation lane and installation function. Registration drives category membership, catalog additions, drag eligibility, and unsupported-target hints. Reuse the optional folders in `catalog.rs` and shared `ControlPanel` rows; do not maintain separate component lists for folders. Do not add component type allowlists to drag handlers. Preview checks must inspect registration metadata without invoking constructors or assigning IDs. Installed transfers continue through core `Project::can_transfer_component` and its transaction. See [component registration](../../../specs/editing/components.md#registering-instrument-components).

- LFO and Envelope use fixed instrument-wide control lanes. Each accepts only its matching provider type; neither accepts effects or audio mix controls. Reuse the shared bus row, lane toolbar, component selection and transfer helpers. Preserve Per note envelope behavior, provider identities and receiving routes during older-project migration. See [modulation lanes](../../../specs/instruments/modulation-lanes.md).

- Register effects once in `effects_catalog.rs::ENTRIES` with a stable type ID, display name, category, and constructor. Reuse `Catalog::with_folders` and the shared `ControlPanel` rows used by the Instrument catalog. Keep folder membership in registration metadata. Enter and library group drops must instantiate selected effects in visible folder order, only on an explicit addition or valid release. Folder browsing and previews must not construct instances or mark the project modified. See [Effects catalog folders](../../../specs/editing/components.md#effects-catalog-folders).

- Catalog selection, keyboard navigation, focus, and row painting use `catalog.rs`. Category folders start collapsed through the shared default; retain user expansion choices as independent UI state for each catalog. Effect entries stay in `effects_catalog.rs`; instrument component entries and addition stay in `instrument_catalog.rs`. Library selection stays separate from installed-unit, layer-target, and track/clip selection. Plain click selects one entry; Shift-click toggles membership. With library keyboard focus, Up/Down moves through visible rows without wrapping; folders receive focus and entries receive selection. Shift+Up/Down extends or shrinks an entry range from its anchor. Enter on an entry adds selected types once per press in visible library order; Enter on a folder toggles it. Closing a folder deselects its hidden entries. Escape or a primary click in empty catalog space clears library selection, including blank header space. Library and installed-unit selections clear when their pane loses focus. Reuse `selection_focus.rs` for pane ownership and keep focus within pane controls and active drags. Keep focus, text editing, selected-track, job/dialog, and drag guards. Dragging a selected library row adds the selected group in library order at the lane insertion line; dragging an unselected row selects that entry. Reuse `effects_reorder.rs` for insertion preview, edge scrolling, release-only commit, and cancellation. Create fresh instances only after a valid drop.

- All shape-selection knobs must use the shared `KnobSpec::diagrams` design. Show a small diagram for each available shape around the knob and highlight the active shape with the accent color. Draw the shape that the control represents (waveform, filter response, drive color response, or envelope curve); do not reuse unrelated diagrams. Keep names in tooltips and accessibility instead of a separate current-shape text label. Two-option mode selectors use the shared bounded two-way knob with both labels at the upper corners; the selected label uses the accent color and the other choice uses secondary text color. Draw a neutral arc between the choices, with no markers or accent value arc. These are mode controls, not shape selectors.

- Reuse `theme.rs`, `panels.rs`, `toolbars.rs`, `rows.rs`, and `dialogs.rs`. Use the `Knob` base widget and `KnobSpec` in `knobs.rs` for every knob type; gain, pan, pitch, and waveform are parameter wrappers over the same interaction and painting code. Keep drag accumulation, Shift sensitivity, keyboard steps, bounds or cyclic wrapping, choice diagrams, reset, focus guards, and accessibility in that base. Use the shared compact knob row to align unit knobs. The Oscillator module owns a list of sources: arrange their knob columns horizontally, place an 18-point circular Plus button inside the add strip on the right, centered on both axes. Reuse the Power button’s circle, border, inactive colors, icon scale, and hover feedback. Keep the painted outer diameter, including the border, equal to the shared 18-point size. The whole add strip is one button: hovering or focusing it highlights its background, and clicking anywhere, including padding, adds one source on release. Expose Remove oscillator on each column and knob. Place an 11-point “Osc N” label to the right of each shared 18-point circular Lucide Power toggle with a 8-point gap. Center the pair below each column’s knobs. Use primary text for active labels and secondary text for muted labels. Retain the source number in the tooltip and accessibility name. On uses the view controls’ accent-tinted fill with a 1-point border and icon in the current accent color. Off uses the secondary text color, matching the dim label, for both icon and border; persist source mute independently of gain and track mute, default missing mute fields to false, and retain zero-output source processing while muted. Paint one 1-point theme-aware divider with half the panel-border contrast between every adjacent strip, including before Add, through the full body from below the header to the bottom border. Each oscillator strip has a fixed 90-point width, including padding, independent of source count. Each strip owns its container and shared padding. Use equal strip heights and apply the shared panel margin on all four sides inside each container, including Add, with no extra inter-strip gap. Use the base knob’s optional value formatter for the small current pitch/gain readouts above the zero/unity mark; retain fixed ticks and endpoint labels. Permit an empty, silent instrument and migrate legacy single-source settings when loading. Oscillator omits parameter-name labels and separate value fields; retain knob tooltips and accessible parameter names. Use `knobs.rs` as the standard knob design and `faders.rs` as the standard gain fader design across the UI. Reuse shared meters, icons, fonts, and waveform helpers.
- Timeline/Editor track headers and regular Instrument layer headers share `mix_controls::header_row`: icon/name or track dropdown in the first row, then Mute/Solo at the left and Pan then Gain at the right in the second row, without numeric fields. Timeline/Editor also share `track_rows::HeaderRows` and a UI-only playback-toolbar toggle between default 42-point one-row tracks and 68-point two-row tracks. In one row, keep icon, name/dropdown, Mute, Solo, Pan, Gain, then meters. Apply that height to lanes, the Editor overview and drop previews; keep Master, Instrument and Mixer layouts independent. Reserve the full name column even for short names. Layer collapse uses the top of each lane’s right toolbar, outside horizontal scrolling. Keep the 6-point M/S gap, 4-point gap between 28-point knob slots, and 7-point outer inset. Output retains only its right-aligned gain knob. Reuse shared toggles and knobs; do not duplicate their interaction or validation logic. Scope layer drafts by stable identity and commit changed settings through `Edit::SetInstrument`. Default missing saved layer mix fields to mute/solo off, gain 0 dB, and pan 0. Layer solo applies only among layers in that instrument; use core `mix_audible` for the same solo-over-mute rule as tracks. Process source sum → Amplitude and its modulation connections → per-layer stereo effect chain → layer gain/pan/audibility → stereo layer sum → Main effects → Main gain/pan → existing track gain/pan → master. Layer panning reuses equal-power coefficients normalized to unity at center, preserving legacy sound and existing track pan behavior. Compatible layer mix edits retain voices, phases, and envelope state, ramp active stereo gains over 5 ms, and apply immediately to idle voice slots so future muted notes stay silent. Keep hidden/muted/solo-excluded sources processing; keep callback retargeting allocation-free. Save these fields in instrument revision 4 with legacy defaults.
- Every installed unit has a 10-point circular on/off control at the left of its header, with no visible label or icon. On headers use the active view-mode button background through shared theme helpers; off headers use the panel’s main border color with muted secondary text in expanded and collapsed states. A collapsed unit keeps the regular panel background for its body and shows only the power control in its 24-point header cap; center the vertical title below that cap with regular panel text when on and muted secondary text when off. The circle uses the full accent color when on; off is hollow with the muted secondary text color. Its hit area is 22 points. In a collapsed strip it remains at the top. Power clicks toggle on release and never collapse or expand the unit, including double-clicks; header double-clicks outside the power control retain collapse behavior. Disabled or unfocused controls do not toggle. The shared `PanelStyle::unit` owns this control and exposes its response for tooltips/accessibility and interaction checks. Unit enable state and collapsed state are saved separately in the project. Older projects default units to enabled and expanded. Oscillator off silences its layer sources without changing their individual settings. Envelope off fades its modulation contribution to neutral; Amplitude off bypasses its gain and modulation through the existing 5 ms note gate. Live source toggles ramp output over 5 ms. Envelope contribution and Amplitude bypass changes fade over 5 ms, retaining held notes, oscillator phase, and envelope progress without callback allocation. Off units remain editable and retain settings when removed/re-added. Playback and export share these states and processing rules.
- Use `PanelStyle::unit` for unit collapse. Double-click an expanded header to replace the body with a full-height strip with a regular panel body and a power-only header cap whose inner width equals the shared header height; double-click the strip to expand. Center the vertical title below the cap, bottom-to-top, with the same font, primary text when on, and secondary text when off. Retain header context menus. Save unit collapse on its audio layer or fixed modulation lane, independently of other units. The shared shell receives mutable project-owned collapse flags, and header double-clicks commit through `Edit::SetInstrument` and mark the project modified. Default missing flags to expanded in older projects. Retain collapse through save/reopen, Save As, row reorder, view/track switches, and unit removal/re-addition; read replacement project values rather than cached UI state. Preserve row height, parameters, and audio processing while hiding the body. Single clicks and disabled controls must not toggle collapse. Future units must reuse this shell.
- Modulation amount knobs must derive from their destination definition in `parameter_knobs.rs`. Reuse the base knob's signed amount adapter for native scales, steps, reference marks, and pointer/Shift sensitivity; keep existing amount units, bounds, and neutral-zero reset. Do not add generic or per-unit amount controls that drift from the destination. See [shared amount knob mappings](../../../specs/modulation/contract.md#destination-matched-amount-knobs).
- Use the standard 10-by-6-point size for every current and future knob choice icon. Reuse `DIAGRAM_SIZE` and the shared diagram renderer in `knobs.rs`, including its 1.25-point stroke. Keep shape paths normalized to the shared icon bounds; do not add per-unit icon sizes. Verify new knob diagrams fit their rows and match the existing waveform/curve dimensions.
- Tracks, Layers, and the Effects catalog are instances of `panels.rs::ControlPanel`. Reuse its shared width, full-height panel background, title/action toolbar, and final right border. Finish the panel after its row content so one neutral, 1-point border remains continuous through the header, selected rows, scrolled rows, and unused space. Individual track and Master frames must not add another right border. Their left edge meets the Effects catalog or Timeline toolbar without a gap; let that adjacent panel own the single 1-point divider instead of adding row/Master left borders. Retain selected-track background fills without selection outlines. The first effect in Timeline or Instrument also shares the toolbar divider: tag its unit scope with `panels::SHARED_LEFT_BORDER_TAG` so `unit_in_lane` omits only that duplicate left stroke. Keep all other unit borders and selection outlines. Reuse `ControlPanel::row_dividers` for row separators. Timeline lanes must take their vertical bounds from their laid-out track panels; draw one separator across the panel and lane instead of positioning an independent lane border. Supply view-specific rows and actions; do not duplicate the column shell.
- Instrument exposes Sources (Oscillator, Sampler), Modulators (Envelope, LFO, Macro), and Processors (Amplitude) folders through a 24-point Piano toolbar toggle directly below the Effects catalog toggle. The Effects and Instrument components catalogs share the same `ControlPanel` position and are mutually exclusive. Timeline Clip settings uses a separate right rail and inspector above the effects lane, composed by `timeline_workspace.rs`, and coexists with left catalogs. Instrument has no Clip settings toggle or panel. Leaving Timeline closes its Clip settings panel and discards its field draft. Editor audio tracks reuse the same fields under Clip options through `clip_settings_body`; share editing, validation, group handling, and worker preparation. Clear drafts and audio previews on view/selection changes. All Timeline catalog panels can be closed. See [Clip settings](../../../specs/editing/clip-settings.md). Reuse `catalog.rs` for mouse/Shift selection, bounded Up/Down and Shift ranges, Enter without repeats, Escape/empty-space clearing, focus, and row painting. Double-click adds the clicked component; Enter adds selected components in catalog order through one `Edit::SetInstrument` to the selected compatible lane. Dragging a selected row carries the selected group in catalog order; dragging an unselected row selects only that entry after the shared movement threshold. Arm on press to support fast motion/release. Drop on any layer label/body, including collapsed or empty layers, to preview that destination and add/select it on release through the same instrument edit. Keep previews clean, scroll vertically near viewport edges, retain catalog focus during drags, and restore it after release. Cancel on Escape, focus loss, disabled/modal UI, hidden catalog, track/view/project changes, changed instrument settings, or outside drops. Block file/view/catalog/track controls while armed. Reuse `catalog.rs` for press-time selection capture and `drag.rs` for pointer, focus, and edge-scroll primitives shared with Effects; instantiate components only after a valid drop. Keep layer selection in UI state, keyed by track/layer identity, with the first layer as the initial/fallback target and the shared selection border on its label. Clicking layer content selects its layer without changing saved data. Preserve target identity through rename/reorder/view changes; project replacement clears it. Oscillator adds one default source. Envelope adds an independent generic modulator; Amplitude restores its optional audio stage without duplicates. Connections live on the receiving Amplitude or Auto-filter unit. A no-op stays clean. Disable additions during jobs/dialogs, text editing, drags, focus loss, or without a valid MIDI layer. Add missing components through the catalog; populated Oscillator panels retain their Plus strip.
- Component unit selection reuses `unit_selection.rs`, `selection_focus.rs`, and the shared panel outline. Command/Ctrl+A selects every installed unit in the focused component or effects lane, including scrolled-out units, through the shared shortcut and selection replacement helpers. Keep text Select All, exact modifiers, repeat/gesture/modal/focus guards, and clean selection-only state. Empty lane clicks retain keyboard focus. Reuse `unit_selection::keyboard_focus` for the non-interactive pane-wide target; zero-area targets lose focus after blank-space clicks. Validate groups through owner `remove_components`; retain removed provider/stage settings and discard removed oscillator sources/pitch routes. Guard modifiers, drags, disabled UI, jobs/dialogs, and pane/window focus. Plain clicks select one unit; Shift-click toggles membership within one lane. Dragging a selected header captures the group in display order through the same helper as effects; dragging an unselected header captures only that unit. Reuse `drag::group_insertion` for group previews and no-op detection. Transfer/copy groups atomically through core `component_group_transfer`; resolve fresh IDs only on valid release and reject the complete group if any member is incompatible. Preserve source-first placement and existing Oscillator/Macro merges, and select the resulting group after release. Keep individual oscillator-strip drags separate from whole-unit selection; keep it independent of layer/catalog selection and project data. Component headers use the shared effects insertion line and drag primitives for same-lane reorder and cross-lane placement, including empty Main. Pin audio sources first. Persist layout through `unit-core::InstrumentComponent` and each owner’s `component_order`; never reorder provider/source vectors to change unit presentation. Retain hidden-unit slots, prune physically transferred IDs, and reject invalid layouts/indices atomically. See [component editing](../../../specs/editing/components.md#selecting-and-reordering-component-units).

No-op releases or unchanged names stay clean. Reordering preserves stable IDs, names, sources, and envelope settings. Add sources and envelopes through the component catalog. Every expanded layer uses the full shared unit-panel height, including empty layers.
