# Three-band EQ

The Effects catalog lists **3-band EQ**. Catalog items use the shared control panel's 8-point padding on every side and the theme's 11-point small text style. Unselected names use the same dim text as inactive view controls. Hover/focus uses default text. A single click selects an item with default text and the active view control's accent-tinted fill; selection is UI-only and retained across view/track switches. Select an audio or MIDI track, then double-click the name to append an instance to its serial effects lane. Single clicks do not add effects or mark the project as modified. Right-click an installed unit header to remove it. Multiple instances keep independent settings and IDs.

The unit reuses the shared unit header, power control, horizontal collapse, knob widget, strip layout, and footer pairs. Three 90-point strips end with Power/Low, Power/Mid, and Power/High. Low and High contain Gain, Frequency, and Q rows. Mid contains only Gain; its footer stays aligned with the outer strips. Footer pairs use the oscillator's 18-point button, 8-point gap, 11-point label, and centered alignment. The Effects catalog header's Up/Down control switches the selected track's lane between the shared 244-point expanded height and 68-point compact height. Compact mode retains headers and footer pairs. Unit headers still collapse horizontally. Effects units omit their bottom border and share the status bar's single thin separator.

| Parameter | Range | Default |
| --- | --- | --- |
| Gain | −24 to +24 dB | 0 dB for each band |
| Frequency | 20 Hz to 20 kHz, logarithmic control | Low 250 Hz; High 2.5 kHz; Mid uses these boundaries |
| Q | 0.1 to 10, logarithmic control | 1/√2 for Low/High; Mid uses these edge controls |

Low and High use shelves. Mid is a middle shelf made from opposing shelves: its Gain sets the plateau between Low and High frequency boundaries. It uses those bands' Q values for its edges and has no independent Frequency or Q controls. A footer control turns its band off without changing saved gain or other parameters. Low off applies a high-pass cut; High off applies a low-pass cut. Mid off rejects the range between the Low and High frequency values. Each outer Q controls its corresponding cut edge's steepness: higher Q uses more low/high-pass stages (one to eight per branch, with interpolation between adjacent stage counts). Crossed shelf frequencies use their lower/upper values as boundaries, retaining each boundary's Q; equal boundaries leave no middle range. Middle shelf gain and cut blend to unity/dry as the boundaries approach one another. Filter transitions occur around the boundaries; this is a finite-order cut, not a brick-wall filter. With all three bands off, the enabled unit produces exact silence after the 5 ms transition, including residual audio in the filters' overlapping transition ranges. Filters keep advancing so re-enabling a band retains their history. The whole unit's header power bypasses all three bands and retains the individual band states.

This replaces the earlier Mid bell and Mid-Q cut design. Version-1 data retains its Mid frequency/Q fields for compatibility; UI and processing ignore them. Loading an earlier EQ instance uses the new middle-shelf behavior while retaining gain, power, and outer parameters.

The track stores an ordered `effects` list, with a stable UUID and typed versioned payload per instance, plus `effects_compact`. EQ state version 1 stores unit power, horizontal collapse, and all band parameters/states. Missing track fields default to an empty chain and expanded lane. Track duplication copies settings and gives each effect a new ID. Save/reopen, Save As, rate changes, and view/track changes retain these fields. Shared core edits validate finite parameter bounds and unique non-nil IDs atomically. Unknown effect types and future EQ versions retain their opaque state, pass audio through, and report a warning on open.

`daw-unit-core` owns the saved format and portable stereo `EffectUnit` contract. `daw-equalizer` contains FunDSP state-variable filters behind that contract, with independent channel state and no device or DAW dependencies. The shared engine processes clip/instrument output → serial EQ instances → track gain/pan and audibility → Master gain. Muted/solo-excluded tracks continue processing. Filter history continues through clip gaps and transport loops; seek and Stop reset it. Pause retains state. Compatible prepared renderer updates preserve filter history by track/effect ID. Gain, frequency, Q, band cuts, and unit bypass changes ramp over 5 ms; presentation changes do not restart ramps. Processing, reset, and retarget do not allocate or block.

Playback and export use the same sequential runtime. There is no added buffering latency. EQ ringing within the arranged render range is processed; export retains the existing arranged duration. Automatic effect-tail export, Master/lane effects, effect drag-reordering, graph editing, and standalone adapters remain future work. Random-access `RenderPlan` helpers warm the state from frame zero when effects are present; use a persistent `Renderer` for sequential or real-time processing.

Native audio-device behavior and Windows/Linux appearance require separate checks from automated filter and egui tests.
